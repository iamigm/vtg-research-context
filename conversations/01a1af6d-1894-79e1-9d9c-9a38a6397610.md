2. **중복을 판단하는 단위**

   |---|---|---|
   | 같은 numeric interval | `[10, 20]`, `[10.0, 20.0]` | 하나의 답 후보로 합치고 생성 경로·출처는 보존 |

3. **어느 정도 가까우면 유사한 후보로 묶을지**

   IoU threshold, start/end 차이, interval 길이 대비 상대 오차 중 무엇을 사용할지 정해야 합니다. IoU만 사용하면 긴 interval에서는 큰 boundary 차이도 유사하게 처리될 수 있고, 절대 시간 차이만 사용하면 짧은 interval에서 중요한 차이를 합칠 수 있습니다.

   묶는 방식도 필요합니다. A–B와 B–C가 유사하지만 A–C는 다른 경우, 연결 관계만으로 모두 합칠지 결정해야 합니다. 저는 **exact interval만 우선 통합하고, 유사도 묶음은 다양성 관리에 사용하는 정책**을 권합니다. 유사도 threshold를 정할 때는 짧은 interval·긴 interval·인접한 반복 occurrence 사례를 함께 확인해야 합니다.

   - **최종 unique 후보가 하나:** 그 후보가 유효하면 추가 비교 없이 반환합니다.

## 2026-11-06T06:08:18.374Z — Codex final report

분기 기준으로 **“이 token을 선택하면, 이후 완성되는 interval의 분포가 어떻게 달라지는가”**를 쓰는 게 좋겠습니다. 원래 video·query prompt를 유지하고, token distribution에서 출발해 다른 시간 가설로 이어지는 경로를 찾는 방식입니다.

GT 없이 확인할 수 있는 것은 **모델이 여러 시간 가설에 확률을 배분하고 있는지, 어느 prefix에서 그 가설들이 갈리는지**입니다. 시간적으로 떨어진 가설을 실제로 다른 occurrence라고 확정하려면 영상 근거가 더 필요합니다. 우선 이를 `temporal mode`로 정의하고 탐색 대상으로 삼을 수 있습니다.

1. **Token entropy와 interval의 불확실성을 구분합니다**

   Token entropy가 높아도 소수점 이하 표기만 달라질 수 있습니다. 반대로 첫 숫자가 확실해도 그 뒤 `.`을 선택하는지, 다른 숫자를 이어 쓰는지에 따라 전혀 다른 시간대로 갈릴 수 있습니다.

   아래는 가상 예시입니다.

   | Continuation 결과 | 관측한 불확실성 | 탐색 방향 |
   |---|---|---|
   | `[12.0,18.0]`, `[12.1,18.0]`, `[11.9,18.2]` | 한 시간대 안의 boundary 차이 | boundary 대안으로 관리 |
   | `[12,18]`, `[104,111]` 주변에 각각 모임 | 분리된 temporal mode | 두 mode로 이어지는 분기 탐색 |
   | `[12,18]`, `[12,45]`, `[12,90]` | end·duration의 불확실성 | 긴 interval이 생기는 경로 검토 |
   | 시간대가 불규칙하게 흩어지고 parsing 실패가 많음 | 불안정한 생성 | 실패율과 mode 재현성 확인 |

   따라서 **완성 interval의 분포를 봐야 분기의 의미를 판단할 수 있습니다.** 서로 동등한 응답을 묶어서 불확실성을 측정하는 [Semantic Uncertainty](https://arxiv.org/abs/2302.09664)가 개념적 참고가 됩니다. 여기서 제안하는 temporal mode는 이번 실험을 위한 별도 정의입니다.

2. **분기 뒤를 여러 번 sampling해서 그 token의 영향을 봅니다**

   원래 prefix를 \(r\), 다음 token을 \(a\)라고 하면, 보고 싶은 것은 다음 분포입니다.

   \[
   P(\text{완성 interval}\mid r,a)
   \]

   진행 방식은 다음과 같습니다.

   - 원래 분포에서 소수의 stochastic rollout을 생성합니다.
   - 공유 prefix와 각 위치의 다음 token distribution을 저장합니다.
   - 관측된 대안 token 뒤에서 start/end가 완성될 때까지 conditional rollout을 추가합니다.
   - token별로 어느 temporal mode에 도달하는지 비교합니다.

   **각 대안 뒤를 greedy로 한 번만 완성하면 continuation의 여러 가능성을 놓칠 수 있습니다.** 추가 연산을 배정할 분기에서는 여러 stochastic continuation을 보는 것이 핵심입니다.

   첫 숫자뿐 아니라 정수 내부·소수점·separator·end 생성 과정까지 살펴봐야 합니다. start가 달라진 경로의 end는 새 start prefix를 조건으로 다시 생성합니다.

3. **‘어떤 token이 시간 가설을 가르는가’를 측정합니다**

   좋은 분기 위치는 다음 token에 따라 도달하는 temporal mode가 달라지는 위치입니다.

   예를 들어 한 prefix에서 다음처럼 관측됐다고 합시다.

   - token A 뒤에서는 대부분 이른 시간대 mode로 갑니다.
   - token B 뒤에서는 대부분 늦은 시간대 mode로 갑니다.

   이 위치는 occurrence 대안을 탐색하는 데 유용합니다. 반면 A와 B 뒤에서 모두 같은 시간대의 소수점 차이만 나온다면 새로운 시간대 탐색에는 기여가 작습니다.

   이를 정량화하는 후보는 **다음 token과 최종 temporal mode 사이의 mutual information**입니다.

   \[
   B(r)=I(A;C\mid r,\text{valid})
   \]

   \(A\)는 다음 token, \(C\)는 완성 interval의 mode입니다. 이 값은 유효한 continuation 안에서 **token 선택이 mode를 얼마나 구분하는지** 나타냅니다. Parsing 실패와 duration 위반의 확률은 별도로 기록합니다.

   다만 적은 rollout으로 계산한 값은 불안정합니다. 아직 충분히 관측하지 못한 분기에는 최소 탐색량을 주고, 표본이 늘어날 때 판단을 갱신해야 합니다.

- **Main sequence:** 각 분기에서 주요 token 집합을 따라간 경로

1. **주요 token 집합:** 누적 확률 질량 기준으로 확보할 token
2. **추가 조사 token 집합:** 주요 집합 밖이지만 확률 지지가 충분한 token
3. **제외 token 집합:** 지지가 너무 약해 분기하지 않을 token

핵심은 2번과 3번을 구분하는 기준입니다.

**최고 확률 token과의 상대 확률에 하한을 두겠습니다.**

현재 prefix에서 최고 token 확률이 \(p_{\max}\)라면, 추가 분기를 허용하는 조건을 다음처럼 잡는 정책안입니다.

\[
p(a\mid r)\ge \max\left(\tau_{\mathrm{abs}},\;\alpha p_{\max}\right)
\]

- \(\alpha\): 최고 token 대비 최소 확률 비율
- \(\tau_{\mathrm{abs}}\): 절대 확률의 최소값

최고 token의 확률에 비례해 하한을 정하는 부분은 [min-p sampling](https://proceedings.iclr.cc/paper_files/paper/2025/hash/afa5f124e36bed5cc2125067005d43f5-Abstract-Conference.html)의 아이디어를 참고할 수 있습니다. 여기에 절대 하한을 추가하는 것은 이번 실험을 위한 제안입니다.

예를 들어 **주요 질량 90%, \(\alpha=0.02\), 절대 하한 0.1%**를 출발점으로 잡으면 다음과 같습니다. 아직 검증된 최적값이라는 뜻은 아닙니다.

| Token | 원래 모델 확률 | 처리 |
|---|---:|---|
| A | 70% | 주요 token |
| B | 20% | 주요 token |
| C | 6% | 추가 조사 |
| D | 3% | 추가 조사 |
| E | 0.9% | 제외 |
| F | 0.1% | 제외 |

최고 확률이 70%이므로 상대 하한은 \(70\%\times0.02=1.4\%\)입니다.

따라서 A·B는 주요 분기로 확보하고, C·D도 조사합니다. E·F에서는 rollout을 열지 않습니다. **이 위치에서 C나 D를 거친 sequence는 tail로 기록**합니다.

여기에는 다음 원칙도 필요합니다.

- **원래 모델 확률로 판정합니다.** 숫자 token만 남긴 뒤 재정규화하거나 temperature를 높여서 작았던 확률을 키운 값으로 하한을 통과시키지 않습니다.
- **질량 목표를 채우려고 하한을 낮추지 않습니다.** 하한 때문에 확보한 질량이 목표에 미달하면 그 사실과 제외 질량을 기록합니다.
- **MI나 새로운 mode의 매력도가 하한을 무효화하지 않습니다.** 하한을 통과한 분기 안에서 MI와 \(S(r,a)\)로 추가 예산을 배정합니다.

이렇게 하면 모델이 한 token에 확신할 때는 분기가 적어지고, 여러 token을 실제로 지지할 때는 분기가 늘어납니다. 모델이 정말 0–9에 비슷한 확률을 주는 경우에는 여러 숫자가 모두 남을 수도 있습니다. 그때는 모델 자체가 여러 대안을 지지하는 상황입니다.

   | Offset fit | 사건의 끝을 놓치거나 불필요한 뒷부분을 포함하지 않았는가? |

   각 기준에 대해 `지지됨 / 반박됨 / 불확실함`을 선택하게 하고, 선택지 확률과 짧은 영상 근거를 기록합니다. 이 값들은 **정답 확률로 해석하거나 서로 곱하지 않습니다.**

   모델이 낮게 평가했다는 이유만으로 parent·siblings·mode 전체를 자동 삭제하지도 않습니다. 우선 상대 비교를 위한 판단과 진단값으로 사용합니다.

   **그다음 두 단계로 비교합니다.**

   - **같은 mode 내부:** 중앙 후보와 boundary 대안을 비교해, 같은 시간 가설에서 더 정확한 interval을 고릅니다.
   - **서로 다른 mode 사이:** mode별 winner를 모두 pairwise 비교해, query에 맞는 시간 가설을 고릅니다.

   비교 질문은 다음 순서를 명시합니다.

   > 먼저 요청한 사건과 occurrence가 맞는지 비교하라. 둘 다 맞는다면 onset과 offset이 더 정확한 interval을 선택하라. 근거가 부족하거나 동등하면 불확실/동률을 선택하라.

   각 pair는 A/B 순서를 바꿔 두 번 평가합니다. 후보가 최대 6개이므로 mode 간에는 최대 15쌍, 양쪽 순서로 30회 비교입니다. Knockout 대신 전체 pairwise 비교의 평균 선호 점수로 최종 후보를 고릅니다.

   순서를 바꾼 두 판단이 충돌하면 확신을 낮게 기록합니다. 최종 동률은 **main 확률 질량 → 고정된 interval 정렬 순서**로 해소합니다.

   **최종 답은 winner의 기존 clipped interval입니다.** 모델에게 timestamp를 다시 생성하게 하지는 않습니다. 후보 판단 단계의 별도 context에서 나온 확률도 원래 rollout probability와 섞지 않습니다.

6. **MI와 \(S\), 모델 판단의 역할 분담**

   세 값은 서로 다른 역할을 맡습니다.

   | 값 | 역할 |
   |---|---|
   | MI | 어떤 token 선택이 temporal mode를 가르는지 분석 |
   | \(S(r,a)\) | 추가 탐색 예산을 어느 경로에 쓸지 결정 |
   | 모델의 영상 판단 | 확보한 main 후보 중 query와 boundary가 맞는 답 선택 |

   이번 초기 실험에서는 **탐색 후 모델 판단** 순서로 둡니다. 판단 결과를 다시 탐색 prompt에 넣지는 않습니다. 이렇게 해야 후보 발견 방식의 효과와 feedback에 의한 분포 변화가 섞이지 않습니다.

   분기별 조사량이 다르므로 단순 생성 빈도를 mode 확률로 쓰지 않습니다. Raw probability와 실제 sampling probability를 모두 기록해 추정에 반영하고, 미탐색 질량과 추정 오차를 함께 표시합니다.

7. **예외 상황과 비교 실험**

   - 같은 sequence가 반복되면 sample 기록은 유지하고, 추론은 cache로 재사용합니다.
   - 같은 interval·mode가 반복되면 새 후보로 세지 않습니다.
   - 유효한 main interval이 하나면 추가 비교 없이 반환합니다.
   - 유효한 main interval이 없으면 실패로 기록합니다. Tail 후보로 대체하지 않습니다.
   - 모델 판단 예산이 부족하면 사전에 정한 중앙 후보를 반환하고 `judge_budget_fallback`으로 별도 표시하는 안입니다.
   - 모델이 후보들에 확신하지 못하면 그 상태를 기록하고, 고정된 상대 비교·동률 규칙으로 선택합니다.

   Probability 기준·token entropy 기준·temporal mode 기준의 세 탐색 조건에 **동일한 clipping·mode 규칙·후보 수·모델 판단 절차**를 적용합니다. Greedy도 같은 clipping으로 평가합니다.

   최종 성능뿐 아니라 **좋은 후보가 있었는지, shortlist에 들어갔는지, 모델이 선택했는지**를 단계별로 분해합니다. Tail에서만 발견한 좋은 mode는 진단 상한으로 분리해 보고합니다.

두 단계로 분리하면, **생성 단계의 목표를 “새 mode를 많이 찾기”에서 “검증기가 좋은 구간을 고르기 쉬운 후보 집합을 적은 비용으로 만들기”로 바꿔야 합니다.** 후보의 개별 품질과 함께, 어떤 후보들을 같이 제안하는지가 중요합니다.

| 총 rollout 상한 | 발견한 후보의 main oracle | 실제 제안한 대표 후보의 oracle | 최종 mIoU |
|---:|---:|---:|---:|
| 32 | 0.7132 | 0.6837 | 0.5266 |
| 256 | 0.7826 | 0.6880 | 0.5265 |

탐색을 늘려 좋은 구간은 더 찾았지만, **그 개선의 대부분이 대표 후보를 추리는 과정에서 사라졌고 최종 성능도 늘지 않았습니다.** 생성된 후보를 제안하는 방식부터 바꿀 필요가 있습니다.

우선 두 단계의 경계를 이렇게 잡겠습니다.

| 단계 | 역할 | 출력 |
|---|---|---|
| 후보 생성 | 경로 탐색, mode 구성, 경계 대안 정리, 제안할 후보 압축 | 작은 후보 집합과 생성 근거 |
| 검증·최종 답안 | 영상으로 후보를 검증하고 최종 구간 결정 | 최종 interval과 판단 근거 |

**대표 interval을 고르는 과정까지 생성 단계에 포함**해야 합니다. 그래야 “좋은 구간을 찾았는데 전달하지 못한 문제”와 “전달했는데 검증기가 고르지 못한 문제”를 분리할 수 있습니다.

제가 우선 시도할 방향은 다음 네 가지입니다.

**1. 새로운 mode 발견뿐 아니라, 유력한 mode의 경계를 더 확실하게 만드는 데 예산을 쓴다.**

현재 novelty 중심 배정은 이미 찾은 mode에서 더 좋은 interval이 나와도 새 mode 발견만큼 보상하지 않습니다. 그런데 최종 답을 개선하는 데 필요한 것이 새로운 사건이 아니라 **이미 유력하게 본 사건의 시작·끝을 바로잡는 것**일 수 있습니다.

예를 들어 여러 경로가 같은 발생 시점을 가리키지만 시작은 안정적이고 끝만 흔들린다면, 시작을 바꾸는 경로를 계속 찾기보다 **그 시작에 조건화한 끝 구간의 대안**을 조사하는 편이 합리적입니다.

생성 예산을 다음 두 용도로 나눕니다.

- **발생 시점 탐색:** 현재 후보와 다른 시간 가설이 있는지 확인.
- **경계 정밀화:** 지지가 있는 mode에서 시작·끝의 불확실성을 줄임.

경계 정밀화도 모델이 실제 생성한 joint interval을 사용해야 합니다. 서로 다른 응답의 시작과 끝을 임의로 조합하거나 평균내는 방식은 피하는 게 좋겠습니다.

**2. Sequence 하나의 확률보다, 같은 시간 가설에 모이는 지지를 본다.**

같은 interval이 여러 표현과 경로로 생성될 수 있습니다. 따라서 개별 sequence의 확률만 보면, 여러 경로에 지지가 분산된 유용한 mode를 낮게 평가할 수 있습니다.

각 mode에는 적어도 다음을 구분해 기록하겠습니다.

| 신호 | 알아보려는 것 |
|---|---|
| Mode에 모이는 모델 확률 질량의 추정 | 모델이 이 시간 가설을 얼마나 지지하는가 |
| 서로 다른 경로에서의 경계 일치 | 특정 경로 하나의 우연한 결과인가 |
| 시작·끝의 불확실성 | 어디를 더 조사하면 후보가 달라질 수 있는가 |
| 유효 interval로 끝나는 비율 | 연산을 쓰고도 후보를 얻지 못하는 분기인가 |

여기서 **많이 sampling됐다는 횟수를 모델 확률로 쓰면 안 됩니다.** Scheduler가 일부 분기를 집중 조사했기 때문입니다. 원래 확률과 sampling 확률을 구분하고, 관측한 질량이 전체 mode 질량의 일부라는 점도 유지해야 합니다.

다만 지지가 높다는 사실이 정답을 보장하지는 않습니다. 이 신호들은 후보 생성의 우선순위이며, 영상 근거에 의한 검증을 대신하지 않습니다.

**3. 후보를 추가할 때의 검증 비용과 혼동까지 고려한다.**

후보가 많으면 oracle은 높아지기 쉽지만, 검증기는 더 많은 비교를 해야 합니다. 현재 round robin에서는 mode 대표가 \(M\)개면 서로 다른 쌍이 \(M(M-1)/2\)개입니다. 순서를 바꿔 묻는 비용도 따라갑니다.

따라서 새 mode를 찾았다고 자동으로 제안하는 대신 이렇게 묻는 겁니다.

> 이 후보가 지금 후보 집합에 추가되면, 더 좋은 답을 고를 기회가 실제로 늘어나는가? 이미 있는 후보를 반복하거나 판단만 어렵게 하지는 않는가?

처음에는 **제안할 mode 수를 고정**하고 비교하는 것이 좋겠습니다. 각 mode에는 기본 대표 하나를 주고, 경계의 대안이 필요한 경우에만 두 번째 interval을 붙입니다. 약한 후보로 자리를 무조건 채울 필요도 없습니다.

이때 중요한 점은 **토큰 확률만으로 검증기의 선택 가능성을 정확히 알 수는 없다는 것**입니다. 원래 질문에 대한 생성 확률과, 후보들을 보여줬을 때 검증기가 선호하는 확률은 다른 분포입니다.

그래서 “선택되기 쉬워 보인다”는 생성 측 신호를 만들더라도, 그 효과는 **고정된 검증기**로 측정해야 합니다. 검증기까지 동시에 바꾸면 무엇이 개선됐는지 알 수 없습니다.

**4. 분기 score를 ‘새로움’에서 ‘후보 집합의 예상 개선량/추가 비용’으로 바꾼다.**

개념적인 목표는 다음과 같습니다.

\[
\text{분기 우선순위}
=
\frac{\text{그 분기를 조사해서 제안 후보 집합이 좋아질 예상량}}
{\text{추가 생성 비용}+\text{추가 검증 비용}}
\]

여기서 예상 개선은 두 종류입니다.

- 기존 후보가 설명하지 못하는, 지지 있는 다른 발생 시점을 찾는 것.
- 기존 유력 mode에서 더 안정적인 경계의 interval을 찾는 것.

반대로 같은 mode의 비슷한 interval만 반복해서 나오거나, 유효 응답을 잘 얻지 못하면 배정을 줄입니다. 이 목적이라면 MI는 보조 진단으로 남기고, **새 mode 수 자체를 직접 보상하는 비중을 낮추는 편**이 맞습니다.

중복 sequence의 재생성을 줄이는 방법도 검토할 수 있습니다. Sequence 단위 sampling without replacement의 한 방법으로 Stochastic Beam Search가 있습니다. 다만 서로 다른 sequence가 같은 mode로 이어지는 문제까지 해결하지는 않습니다. [공식 논문](https://proceedings.mlr.press/v97/kool19a.html)

마지막으로, **“선택될 가능성을 올린다”는 목표도 정확히 정의해야 합니다.** 아무 후보나 검증기가 강하게 선호하도록 만드는 것은 목적이 아닙니다. 우리가 원하는 것은 다음입니다.

> **좋은 후보를 제안했을 때, 그 후보가 실제 최종 답의 성공으로 이어지는 비율을 높인다.**

이를 평가할 때는 oracle 외에 다음을 함께 보겠습니다. GT는 모두 사후 평가에만 사용합니다.

- **제안 후보 oracle:** 생성 단계가 실제로 전달한 후보 안에 좋은 답이 있는가?
- **좋은 후보가 있을 때의 최종 성공 비율:** 예를 들어 제안 후보 중 IoU≥0.5가 있을 때, 최종 답도 IoU≥0.5가 되는가?
- **선택 손실:** 제안 후보 oracle − 최종 IoU.
- **전체 비용:** 후보 생성과 검증을 합쳐 얼마를 썼는가?

우선 실험은 **검증기를 고정하고, 후보 수를 맞춘 상태에서 현재 novelty 중심 생성과 ‘유력 mode의 경계 정밀화’를 함께 하는 생성을 비교**하는 것을 제안합니다. 이것이 oracle 증가가 실제 선택으로 이어지는지 가장 직접적으로 확인할 수 있는 첫 비교입니다.

방향은 타당합니다. 다만 **“시간 구간을 명확히 구분한다”와 “두 구간을 서로 겹치지 않게 만든다”를 구별해야 합니다.** 같은 사건의 경계 대안은 겹치는 것이 자연스럽고, 서로 다른 사건도 동시에 일어날 수 있기 때문입니다.

논문에서 가져올 핵심은 **후보의 유망함과 semantic diversity를 분리하고, 다양성이 낮은 곳의 추가 탐색을 줄인다**는 원칙입니다. 논문은 형제 action의 embedding 간 cosine distance를 사용합니다. 하지만 숫자 한 자리 차이로 답이 달라지는 경우에는 이론적 가정이 성립하지 않을 수 있다고도 명시합니다. 따라서 우리의 timestamp 응답에 그대로 적용할 근거는 부족합니다. [논문 §4·Appendix D](https://arxiv.org/pdf/2610.22858)

아래는 이를 우리 후보 생성에 적용하기 위한 설계 제안입니다.

**1. 우선 현재 mode를 ‘서로 다른 사건’으로 취급하는 것을 멈추는 게 맞습니다.**

현재 clustering은 interval끼리 가까운지를 판단합니다. 그래서 하나의 사건에 대한 경계 예측이 넓게 흩어져 있으면 여러 mode로 쪼개질 수 있습니다. 서로 다른 mode인데 실제 영상은 거의 같은 문제가 생기는 것입니다.

우선 후보들 사이의 관계를 다음처럼 분류하겠습니다.

| 시간 구간의 관계 | 가능한 해석 | 우선 처리 |
|---|---|---|
| `[10,20]`, `[10.4,20.6]`처럼 경계만 조금 다름 | 같은 발생 시점의 경계 불확실성 | 하나의 가설 안에 경계 대안으로 보관 |
| `[10,15]`, `[30,35]`처럼 충분히 떨어짐 | 서로 다른 발생 시점 | 별도 가설로 유지 |
| `[10,20]`, `[15,25]`처럼 일부가 겹침 | 경계 차이 또는 인접한 다른 사건 | 구분 보류, 차이가 나는 부분 조사 |
| `[10,30]`, `[14,18]`처럼 포함 관계 | 전체 행동과 세부 동작 또는 불필요하게 긴 예측 | 범위가 다른 가설로 보관 |
| 차이가 실제 입력 프레임으로 구별하기 어려울 만큼 작음 | 현재 영상 입력으로는 판단 불가 | 별도 사건으로 세지 않음 |

핵심은 **모든 후보 쌍을 즉시 ‘같음/다름’으로 확정하지 않는 것**입니다. ‘구분 보류’를 정식 상태로 두어야 합니다.

**2. 시간적 구분은 단일 대표 interval보다 ‘경계의 분포’를 보고 결정하겠습니다.**

한 mode의 대표가 `[10,20]`이라고 해도, 실제 생성된 interval들이 `[9,19]`부터 `[14,24]`까지 퍼져 있다면 경계는 불확실합니다. 대표 하나만 비교해서 두 사건이라고 정하면 위험합니다.

기존 rollout으로 다음을 먼저 구성할 수 있습니다.

- 시작과 끝을 함께 보는 **`(start, end)`의 2차원 분포**.
- 각 시간대가 interval에 포함되는 정도.
- 생성 경로들이 일관되게 포함하는 중심 부분과, 경계가 흔들리는 주변 부분.

같은 시간 가설에 지지가 연속적으로 모여 있다면 경계 대안으로 관리합니다. 반대로 **지지가 두 곳에 모이고 그 사이에는 낮은 지지의 영역이 있으며, 조금씩 경계를 바꿔도 그 구분이 유지된다면** 별도 시간 가설로 볼 근거가 생깁니다.

이 방식도 자동으로 정답을 알려주지는 않습니다. 다만 현재처럼 발견 순서대로 가까운 interval을 묶는 것보다, **분리된 두 가설인지 하나의 넓은 불확실성인지**를 직접 살펴볼 수 있습니다. 질량을 구성할 때는 adaptive sampling 횟수를 그대로 확률로 쓰지 않아야 합니다.

**3. 나누어 떨어지지 않으면 자르지 말고, 공통 부분과 차이가 나는 부분을 분리해서 보겠습니다.**

예를 들어:

```text
A: [10 ───────── 20]
B:       [15 ───────── 25]

A만 포함: [10,15]
공통 부분: [15,20]
B만 포함: [20,25]
```

두 interval 전체를 각각 요약하면 공통 부분 때문에 같은 설명이 나올 수 있습니다. 따라서 확인할 것은 다음입니다.

- 공통 부분에서는 어떤 행동이 보이는가?
- A에만 포함되는 부분에는 다른 행동이나 사건의 시작이 있는가?
- B에만 포함되는 부분에는 다른 행동이나 사건의 끝이 있는가?

차이 나는 부분에서도 같은 행동이 이어진다면 경계 불확실성으로 묶을 근거가 됩니다. 다른 행동이나 명확한 전환이 보이면 별도 가설로 유지할 근거가 됩니다.

차이 나는 부분이 너무 짧거나 가려져 있다면 **구분 보류를 유지**합니다. 이때는 상위 가설 하나에 여러 boundary 대안을 붙여 보관하고, 새 사건을 발견한 것처럼 novelty 보상을 주지 않는 편이 좋겠습니다.

포함 관계도 중간 시각으로 잘라서는 안 됩니다. 긴 interval이 여러 행동을 포함하는지, 짧은 interval이 그중 특정 동작만 담는지를 따로 살펴야 합니다.

**4. Semantic은 timestamp 문장이 아니라 해당 영상 내용에서 측정해야 합니다.**

`The event happens in 10–15 seconds`와 `…30–35 seconds`의 embedding은 문구가 거의 같아서 비슷할 수 있습니다. 반대로 숫자가 다르다는 이유만으로 embedding이 달라져도 사건 의미가 다르다는 근거는 되지 않습니다.

우선 두 수준을 구분해서 측정하는 것이 좋겠습니다.

| 측정 | 방법 | 주의할 점 |
|---|---|---|
| 저비용 영상 차이 | 기존 영상 encoding을 재사용해 해당 시간대의 feature를 비교 | 배경 차이와 행동 차이를 혼동할 수 있고, 단순 평균은 행동 순서를 잃음 |
| 행동 의미의 차이 | 각 구간에서 인물·행동·대상·전후 상태를 짧게 기술하고 비교 | 설명 생성 비용과 hallucination을 별도로 관리해야 함 |

짧은 기술을 만들 때는 원래 query의 정답을 확인하라고 묻기보다, **그 구간에서 관측되는 내용을 독립적으로 기술**하게 하는 편이 좋겠습니다. 설명에서 timestamp를 제거해야 숫자 차이를 semantic 차이로 잘못 세는 것도 줄일 수 있습니다.

여기서도 중요한 구분이 있습니다.

> **서로 떨어진 두 구간에서 같은 사람이 같은 행동을 반복했다면, semantic은 비슷해도 서로 다른 발생 시점입니다.**

따라서 semantic similarity가 높다는 이유만으로 두 시간 가설을 합치면 안 됩니다. **행동 종류의 유사성**과 **동일한 발생 시점인지**를 별도로 관리해야 합니다.

**5. 이 신호가 실제로 탐색 비용을 줄일 수 있는지는 따로 검증해야 합니다.**

모든 rollout을 끝낸 다음 semantic을 측정하면 결과 해석에는 도움이 되지만, 이미 쓴 탐색 비용을 줄이지는 못합니다.

실제 적용을 목표로 한다면 소수의 초기 continuation에서 임시 interval들을 얻고, 그 영상 내용의 차이가 **이후 continuation의 새로운 시간 가설 발견량을 예측하는지** 확인해야 합니다. Semantic 추출에 드는 추가 비용도 포함해야 하고요.

첫 진단은 다음 순서가 적절하겠습니다.

1. 기존 생성 결과에서 **시간적으로 명확히 다른 경우·경계 차이·구분 보류**를 나눈다.
2. 명확히 구분되는 경우부터 영상 기반 semantic을 측정한다.
3. 겹치는 경우에는 공통 부분과 차이 나는 부분을 따로 측정한다.
4. 초기 semantic 차이가 작았던 분기를 더 탐색했을 때 실제로 중복이 많았는지 확인한다.

## 2026-11-08T16:08:09.465Z — Codex final report

**对，可以，而且这比把时间区间换成 embedding 再估计 dispersion 更直接。** 我们可以保持现有 decoding 不变，另外测量这些量。不过要区分：**时间数值的 variance**和论文公式里的 **entropy 的 variance**不是同一个东西。

论文在固定状态 \(r\) 下定义：

- \(A\)：接下来选择的 action。
- \(Y\)：继续生成后得到的最终答案。
- \(h(a)=H(Y\mid r,A=a)\)：选择某个 action 后，最终答案还剩多少不确定性。

它关心的两个量是：

\[
\mu_H=\mathbb E_A[h(A)],\qquad
\sigma_H^2=\operatorname{Var}_A[h(A)]
\]

论文将 \(h(a)\) 视为不能直接观测的量，再用 action embedding 的 dispersion 建立联系。我们可以通过重复 continuation，**对每个分支的 \(h(a)\) 本身做 Monte Carlo 估计**。数字输出并不会让 entropy 自动变成精确可知，但让最终答案空间及其几何关系更容易明确。 [论文 §3.2](https://arxiv.org/pdf/2610.22858#page=4)

**在我们的实验里，可以同时测三类东西。**

| 测量 | 回答的问题 |
|---|---|
| \(\mathbb E_A[H(Y\mid r,A)]\) | 选完下一分支后，平均还剩多少区间不确定性？ |
| \(\operatorname{Var}_A[H(Y\mid r,A)]\) | 不同分支留下的不确定性，差别有多大？ |
| \(\operatorname{Cov}((S,E)\mid r)\) | 最终生成的开始、结束时间在时间轴上散得多开？ |

第三项不需要 semantic embedding。它可以直接报告开始时间 variance、结束时间 variance，以及二者的 covariance；跨不同长度的视频比较时，还可以同时报告按视频长度归一化后的版本。

**实际测量要用两层 sampling。**

固定一个真实 decoding prefix \(r\)，把下一 token 作为分支 \(A\)：

1. 记录各允许分支的概率 \(p_a\)。
2. 对每个分支 \(a\)，独立生成多次完整 continuation。
3. 将结果解析为 interval，得到该分支下的答案分布 \(\hat p(y\mid r,a)\)。
4. 估计每个分支的 entropy：
   \[
   \hat h_a=-\sum_y\hat p(y\mid r,a)\log_2\hat p(y\mid r,a)
   \]
5. 根据分支概率汇总：
   \[
   \hat\mu_H=\sum_a p_a\hat h_a,\qquad
   \hat\sigma_H^2=\sum_a p_a(\hat h_a-\hat\mu_H)^2
   \]

因为我们已经有下一 token 的概率，**外层 expectation 可以直接加权求和**；主要的 Monte Carlo 成本在每个分支的后续 interval 分布。

例如两个分支各有50%概率：

| 分支 | 后续完整 interval | 分支内 entropy |
|---|---|---:|
| A | 总是 `[10,12]` | 0 bit |
| B | `[30,32]`、`[40,42]`各一半 | 1 bit |

那么平均剩余 entropy 是 **0.5 bit**，不同分支的 entropy variance 是 **0.25 bit²**。

反过来，如果 A 总是生成 `[10,12]`，B 总是生成 `[40,42]`，则两者的剩余 entropy 都为0，entropy variance也为0，**但时间数值的 variance很大**。这说明它们分别测量“分支内还有多少不确定性”和“结果相隔多远”。

**需要先固定几个定义，才能让测量有意义。**

- **Interval entropy的分辨率。** 建议首先用固定的二维 `(start, end)` 网格，而不是当前 mode clustering。否则0.01秒的表达差异也可能被算成不同答案，entropy会受输出精度影响。可以在几个固定时间分辨率下同时报告结果。
- **Sampling对应的分布。** 当前有概率下限和main/tail限制，测到的是这些限制下的分布，不能直接称为原始全 vocabulary policy 的结果。先明确一个目标分布，再使用它对应的分支权重和continuation。
- **无效响应。** Entropy可以把解析失败作为单独类别；数值 covariance则在有效 interval中计算，并同时报告有效率。
- **估计误差。** 有限样本的 entropy有偏差，分支间的 \(\hat h_a\) 差异也混有估计噪声。因此要比较不同 continuation 数下的稳定性，不能把估计值当成精确量。

还有一个关键点：**不能拿 token ID计算“数字 variance”**。Token可能是数字片段或混合符号，没有统一的时间单位。最稳妥的是保留真实token分支，用它们生成的完整 `(S,E)` 来测数值 dispersion。如果把已经完整输出的 interval本身定义成action，而最终答案也是该interval，条件 entropy就会退化为0。

所以这次可以把目标明确为：**既不剪枝，也不调整预算，只测量数值 dispersion、平均剩余 entropy和entropy variance，再观察它们与候选视频的semantic差异是否对应。** 这能直接检验“时间上分散的答案，是否真的代表内容上不同的假设”。

- \(Y\): 그 분기에서 계속 생성한 최종 답.
- \(h(a)=H(Y\mid r,A=a)\): 분기 \(a\)를 선택한 뒤에도 남아 있는 최종 답의 불확실성.

논문에서 다루는 평균과 variance는 다음입니다.

\[
\mu_H=\mathbb E_A[h(A)],\qquad
\sigma_H^2=\operatorname{Var}_A[h(A)]
\]

우리는 각 분기에서 continuation을 반복 생성해 \(h(a)\) 자체를 추정할 수 있습니다. 다만 숫자로 답한다고 해서 entropy가 정확히 알려지는 것은 아닙니다. **명확하게 정의한 숫자 공간에서 추정할 수 있다**는 것이 장점입니다. [논문 §3.2](https://arxiv.org/pdf/2610.22858#page=4)

**우리 실험에서는 세 가지를 함께 측정할 수 있습니다.**

| 측정값 | 의미 |
|---|---|
| 평균 잔여 entropy \(\mathbb E_A[H(Y\mid r,A)]\) | 다음 분기를 선택하고 나면, 평균적으로 얼마나 불확실성이 남는가? |
| 잔여 entropy의 variance | 어떤 분기는 결과가 확실하고, 어떤 분기는 여전히 불확실한가? |
| 최종 interval의 covariance \(\operatorname{Cov}((S,E)\mid r)\) | 생성된 시작·끝 시각이 시간축에서 얼마나 넓게 퍼지는가? |

세 번째는 시작 시간의 variance, 종료 시간의 variance, 시작·종료 사이의 covariance로 직접 계산할 수 있습니다. 영상 길이가 다른 경우에는 초 단위 값과 영상 길이로 정규화한 값을 함께 보면 됩니다.

**측정은 분기별로 continuation을 반복 생성하는 방식입니다.**

1. 실제 decoding prefix \(r\) 하나를 고정합니다.
2. 다음 token별 분기 확률 \(p_a\)를 기록합니다.
3. 각 분기 \(a\)에서 완성된 응답을 여러 번 생성합니다.
4. 완성된 interval의 분포로 분기별 entropy \(\hat h_a\)를 추정합니다.
5. 분기 확률로 가중해 평균과 variance를 구합니다.

\[
\hat h_a=-\sum_y \hat p(y\mid r,a)\log_2\hat p(y\mid r,a)
\]

\[
\hat\mu_H=\sum_a p_a\hat h_a,\qquad
\hat\sigma_H^2=\sum_a p_a(\hat h_a-\hat\mu_H)^2
\]

다음 token의 확률은 이미 알 수 있으므로 **바깥쪽 expectation은 직접 가중합으로 계산**할 수 있습니다. Monte Carlo 추정이 주로 필요한 것은 각 분기 이후의 interval 분포입니다.

예를 들어 두 분기의 확률이 각각50%라고 하겠습니다.

| 분기 | 완성된 interval | 분기 내부 entropy |
|---|---|---:|
| A | 항상 `[10,12]` | 0 bit |
| B | `[30,32]`, `[40,42]`가 각각50% | 1 bit |

이 경우 평균 잔여 entropy는 **0.5 bit**, 잔여 entropy의 variance는 **0.25 bit²**입니다.

반대로 A는 항상 `[10,12]`, B는 항상 `[40,42]`를 생성한다면 두 분기의 잔여 entropy는 모두0입니다. 따라서 entropy의 평균과 variance도0이지만, **시간 숫자의 variance는 큽니다.**

즉, 서로 다른 질문에 답합니다.

- 숫자 variance: **결과 구간들이 얼마나 떨어져 있는가?**
- 평균 잔여 entropy: **분기를 선택해도 결과가 얼마나 흔들리는가?**
- 잔여 entropy의 variance: **그 흔들림이 분기마다 얼마나 다른가?**

**정확한 측정을 위해서는 다음 정의가 필요합니다.**

- **Interval entropy의 시간 분해능:** 처음에는 고정된 `(start, end)` 격자를 사용하는 것이 좋겠습니다. 그렇지 않으면0.01초의 표현 차이도 별개의 답으로 세어질 수 있습니다. 현재 mode clustering과 독립적으로 측정할 수 있다는 장점도 있습니다.
- **측정 대상 분포:** 현재 확률 하한과 main/tail 제한을 적용했다면, 그 제한 아래의 sampling 분포를 측정한다고 명시해야 합니다. 원래 모델 전체 분포와 혼동하면 안 됩니다.
- **무효 응답:** Entropy에는 별도 실패 범주로 포함할 수 있습니다. 숫자 covariance는 유효 interval에서 계산하고 유효율을 함께 보고합니다.
- **추정 오차:** 분기별 entropy 추정치 자체에도 오차가 있습니다. 따라서 그 추정치들의 variance를 곧바로 정확한 entropy variance로 해석하지 않고, continuation 수에 따른 안정성도 확인해야 합니다.

또한 **token ID 자체의 variance를 계산하는 것은 의미가 없습니다.** Token은 숫자 조각이나 구분자를 포함할 수 있기 때문입니다. 실제 token 분기는 그대로 두고, 그 결과로 완성된 `(S,E)`에 수치적 variance를 계산하는 것이 타당합니다.

따라서 이번 분석은 **기존 decoding을 바꾸지 않고, 수치적 분산·평균 잔여 entropy·잔여 entropy의 variance를 측정하는 것**으로 잡으면 됩니다. 이후 영상 embedding과 비교하면 **“숫자로 다른 구간이 실제 영상 내용에서도 다른가?”**까지 연결해서 볼 수 있습니다.

|---|---|

2. 누적 확률이 **0.99에 도달하는 token까지** top-p 집합에 넣습니다.
3. 그 안에서도 **원래 확률이 1% 미만인 token은 제외**합니다.
4. 남은 token으로 이어지는 경로를 모두 추적합니다.

즉, 허용 집합은 다음입니다.

\[
\mathcal A(r)=\operatorname{TopP}_{0.99}(r)
\cap\{a:p_\theta(a\mid r)\ge0.01\}
\]

- 정확히1%인 token은 포함합니다.
- 하한 적용 후 남은 확률 질량이99%보다 작아도, 낮은 확률의 token을 추가하지 않습니다.
- 1%는 허용 token끼리 재정규화하기 **전**의 확률입니다.
- 허용 token이 하나도 없으면 해당 경로는 그 지점에서 종료 사유를 기록합니다.

**2. 완성된 경로를 interval 확률분포로 변환**

완성 경로 \(\pi\)의 확률은 원래 token 확률의 곱으로 계산합니다.

\[
P_\theta(\pi)=\prod_t p_\theta(a_t\mid a_{<t},x)
\]

각 응답에서 interval을 parsing하고, 기존대로 endpoint를 `[0, 영상 길이]`에 clipping합니다. 이후 `start < end`인 구간만 유효합니다.

서로 다른 경로가 같은 clipped interval을 만들면 확률을 합칩니다.

\[
W(s,e)=
\sum_{\pi:\operatorname{interval}(\pi)=(s,e)}
P_\theta(\pi)
\]

이렇게 얻는 것은 **원래 모델 분포 중 추적 규칙을 통과해 유효한 interval로 끝난 부분**입니다. 전체 모델 분포와 같지는 않습니다.

따라서 두 값을 함께 보관하겠습니다.

- **원래 확률 질량 \(W(s,e)\):** 모델 전체 분포에서 확보한 지지.
- **유효하게 추적된 결과 안의 정규화 분포:** 구간들의 상대적 비중을 비교하는 용도.

하한 등으로 제외된 질량, 무효 응답의 질량, 미완성 경로의 질량도 별도로 남깁니다.

**3. 분기 시점마다 측정할 값**

| 측정값 | 의미 |

여기서 평균 유사도와 내부 dispersion은 모든 구간 쌍을 직접 비교하지 않고도 계산할 수 있습니다.

정규화한 구간 벡터를 \(z_i\), 그룹 안의 확률 가중치를 \(w_i\)라 하면, 임시 가중 평균은

\[
\mu_G=\sum_i w_i z_i
\]

입니다. 이 값으로 다음을 정확히 계산할 수 있습니다.

\[
\text{그룹 내부 dispersion}=1-\|\mu_G\|^2
\]

\[
\text{그룹 A·B 사이의 가중 평균 cosine}
=\mu_A^\top\mu_B
\]

내부 dispersion은 **그 그룹의 영상 내용이 한 방향으로 모이는지, 여러 방향으로 흩어지는지**를 나타냅니다. 첫 번째 식은 자기 자신을 포함한 확률분포 기준이며, 서로 다른 구간 쌍만의 평균이 필요하면 가중치로 보정해 따로 표시하겠습니다.

이 계산에 쓰는 평균 벡터도 통계 변환 후에는 삭제할 수 있습니다. 따라서 대규모 pairwise 계산과 영구 벡터 저장을 모두 줄일 수 있습니다.

이 저장안으로는 정해진 그룹의 내부 다양성, 그룹 간 유사도, 모델·pooling 차이를 비교할 수 있습니다. 하지만 나중에 **새로운 clustering을 적용하거나 저장하지 않은 두 clip의 정확한 유사도를 요구하면**, 해당 clip을 다시 encoding해야 합니다.

**다음 token의 확률뿐 아니라, 경로 전체에 남아 있는 확률 질량에 제약을 거는 게 좋겠습니다.**

제가 제안하는 제약은 다음 순서입니다.

| 제약 | 처리 방법 | 한계 |
|---|---|---|
| **출력 형식** | 합의한 구간 형식과 소수점 한 자리만 허용 | 형식 밖 응답의 확률은 별도로 기록해야 함 |
| **명백히 무효인 구간** | 더 이어 써도 유효한 구간이 될 수 없는 prefix는 종료 | 숫자가 아직 완성되지 않았다면 섣불리 판단하면 안 됨 |
| **미탐색 확률 질량** | 확률 질량이 큰 prefix부터 탐색하고, 남은 질량이 충분히 작으면 종료 | 전체 분포의 정확한 통계 대신 탐색한 부분의 통계가 됨 |

가장 중요한 것은 세 번째입니다.

현재는 시작 숫자에서 1%, 종료 숫자에서 1%를 선택한 조합도 끝까지 봅니다. 두 선택만 곱해도 경로 지지는 **0.01%**이고, 앞뒤 token 확률까지 곱하면 더 작아집니다. 따라서 **각 선택이 허용되는지**와 **그 조합을 끝까지 조사할 가치가 있는지**를 구분해야 합니다.

다만 “경로 확률이 일정 값보다 낮으면 제거”만으로는 부족합니다. 작은 경로가 아주 많으면 합친 질량은 클 수 있기 때문입니다. 대신 다음 두 값을 관리하겠습니다.

- \(V\): 지금까지 완성한 **유효 구간들의 원래 확률 질량**
- \(U\): 아직 탐색하지 않은 prefix들의 확률 질량 합계

각 prefix의 질량은 그 아래에서 앞으로 얻을 수 있는 유효 질량의 상한입니다. 따라서

\[
\frac{U}{V+U}\leq \epsilon
\]

이면, **최종 유효 구간 분포에서 놓친 질량이 최대 \(\epsilon\)**이라고 보수적으로 말할 수 있습니다. 고정 경로 수 대신 이런 종료 기준을 쓰자는 제안입니다. 현재의 token별 top-p=0.99와는 별도의 기준입니다.

우선 일부 query에서 **미탐색 질량 허용치 1%·5%·10%**를 비교하는 것이 좋겠습니다. 후보 구간과 temporal group이 얼마나 유지되는지, 비용이 얼마나 줄어드는지 보면 됩니다. 단, 잘린 분포의 entropy·variance를 전체 분포의 정확한 값으로 표시해서는 안 됩니다.

그리고 확률이 수만 개 구간에 실제로 넓게 퍼져 있다면, 99%를 확인하는 데도 많은 연산이 필요합니다. 그 경우에는 **모든 미세한 경계 조합을 정확히 측정하려는 목표 자체의 비용**이라는 점을 결과로 보여줘야 합니다.

|---:|---:|

특히 **LevinTS**는 다음 값이 작은 prefix부터 확장합니다.

\[
L(n)=\frac{d(n)}{\pi(n)}
\]

여기서 \(\pi(n)\)은 해당 prefix까지의 경로 확률이고, \(d(n)\)은 깊이입니다. **같은 깊이면 고확률 경로를 먼저**, 같은 확률이면 짧은 경로를 먼저 봅니다. 높은 확률을 우대하면서도, 깊게 이어지는 한 경로가 탐색을 계속 점유하는 것을 완화합니다. 다만 이 논문의 목표 도달 보장이 temporal mode coverage나 GT 성능을 보장하는 것은 아닙니다.

우리 실험에는 다음 구성을 제안합니다. 이는 위 논문들을 참고한 **우리의 적용안**입니다.

1. **주된 예산은 남은 native 확률 질량에 비례해 배분합니다.**
   \[
   B_i \approx B\frac{U_i}{\sum_j U_j}
   \]
   \(U_i\)는 서로 겹치지 않는 분기 그룹 아래의 미탐색 질량입니다. 예를 들어 질량이 70%·20%·10%라면 기본 배분도 그 비율을 따릅니다.

2. **각 그룹 안에서는 LevinTS를 비교 기준으로 사용합니다.**  
   현재의 확률 우선 순서와 `깊이/경로 확률` 순서를 같은 연산 예산에서 비교하겠습니다. 실제 비용에는 KV rollback과 prefix replay도 포함합니다.

3. **상위 분기의 기본 조사는 그 분기에 배정된 예산에서 수행합니다.**  
   별도의 큰 균등 예산을 떼어두지 않고, 상위 분기가 한 번도 완성되지 않은 경우만 보완 대상으로 관리합니다.

4. **예산 후반에는 완성 가능한 경로를 우선합니다.**  
   보류한 새 분기의 질량은 미탐색 질량으로 계속 남깁니다. 종료 기준은 기존처럼 **미탐색 질량 1% 또는 연산 예산 소진**입니다.

또한 DORA를 참고하더라도, **서로 다른 sequence가 같은 구간에 도달한 native 확률은 합쳐야 합니다.** 후보 개수가 많다는 이유로 예산을 더 주는 것과, 실제 모델 확률 질량이 큰 것은 구분하겠습니다.

## 2026-11-08T20:17:19.468Z — Codex final report

**최종 답변까지의 깊이는 미리 모릅니다. LevinTS에서 쓰는 깊이는 ‘현재 prefix까지 이미 생성한 token 수’입니다.**

예를 들어 답변을 지금까지 10 token 생성했다면 \(d(n)=10\)이고, 다음 token을 붙인 자식은 \(d=11\)입니다. Video·query 입력 token은 제외합니다.

따라서

\[
L(n)=\frac{d(n)}{\pi(n)}
\]

은 **현재 깊이와 현재까지의 경로 확률로 다음에 확장할 prefix를 고르는 규칙**입니다. 완성까지 남은 길이나 추가 비용을 미리 계산한 값은 아닙니다.

앞서 제가 “짧은 경로를 먼저 본다”고 한 표현은 **현재까지 얕은 prefix를 우대한다**는 뜻으로 한정해야 정확합니다. “예산 안에 완성 가능한 경로를 우선한다”는 별도의 남은 길이 추정이 필요하며, LevinTS 점수만으로는 알 수 없습니다.

그래서 우리 실험에서도 **현재 깊이를 사용하는 우선순위**와 **완성까지의 추가 비용 추정**을 분리해서 다뤄야 합니다.

원래 LevinTS도 전역 frontier의 최소 점수 node를 선택합니다. 현재처럼 하나를 선택하고 EOS까지 greedy로 진행하면 중간에 더 우선적인 다른 prefix를 건너뛸 수 있습니다. 따라서 [현재 greedy spine 부분](/home1/irteam/experiments/zero-shot/_lib/path_mass_runtime.py:65)을 바꿔야 합니다. Greedy 구간도 다른 frontier보다 계속 우선인 경우에만 연속 처리할 수 있습니다. [LevinTS 원문](https://proceedings.neurips.cc/paper/2018/file/52c5189391854c93e8a0e1326e56c14f-Paper.pdf)

Top-p=0.99·확률 하한 1%·소수 자릿수 greedy 정책도 유지할 수 있습니다. 이 경우 자식 확률의 합이 1보다 작은 tree가 됩니다. 관련 확장인 PHS는 이러한 확률 구조를 명시적으로 허용합니다. 다만 보장 대상은 **이 정책으로 남긴 tree**입니다. 또한 첫 해를 찾는 원래 종료 조건을 여러 후보 수집과 미탐색 질량 1% 조건으로 바꾸므로, 전체 절차를 원본 그대로라고 부르지는 않겠습니다. [PHS 원문](https://arxiv.org/html/2103.11505)

별도로, **node expansion 수에 대한 보장을 GPU 연산량 보장으로 해석하면 안 됩니다.** KV rollback·prefix replay 비용은 실제 decoder 입력 수와 GPU 시간으로 측정해야 합니다.

**Reward는 ‘정답 평가’보다 ‘후보 탐색 효용’으로 정의하는 것이 맞겠습니다.**

DORA 원형은 PRM 점수와 embedding 기반 uniqueness를 결합합니다. 우리는 그 자리에 **native 확률 질량과 시간 구간의 중복도**를 넣는 별도 변형을 만들 수 있습니다. 원래 DORA의 최적성 보장을 그대로 가져오는 것은 아닙니다. [DORA 원문](https://arxiv.org/html/2506.15707v1)

제안하는 배분식은 다음입니다.

\[
w_i=
\frac{U_i(1+\lambda q_i)}
{\sum_j U_j(1+\lambda q_j)}
\]

- \(U_i\): 서로 겹치지 않는 subtree별 **남은 native 확률 질량**
- \(q_i\in[0,1]\): 이미 완성한 구간에서 측정한 **시간적 새로움**
- \(\lambda\): 새로움이 예산에 미치는 영향을 제한하는 계수

시간적 새로움은 우선 간단하게 계산할 수 있습니다.

\[
\nu(I)=1-\max_{J\in\mathcal C_{\text{other}}}\operatorname{tIoU}(I,J)
\]

다른 분기의 기존 후보와 많이 겹치면 낮고, 떨어져 있으면 높습니다. 분기별 \(q_i\)는 완성한 유효 구간들의 \(\nu\)를 native 확률로 가중한 평균으로 둡니다. **이것은 semantic 차이나 정답 여부를 의미하지 않습니다.**

아직 구간을 완성하지 못한 분기는 새로움을 모릅니다. 보정 없이 \(U_i\)만으로 시작하고, 후보가 생긴 뒤 갱신합니다. 무효인 완성 구간은 후보에서 제외하되, 한 번의 greedy 완성이 무효였다고 subtree 전체를 제거하지는 않습니다.

초기 비교는 \(\lambda=0\)과 \(0.1\)이 좋겠습니다. \(0.1\)이면 새로움에 따른 **상대 배분 비율의 변화가 최대 1.1배**로 제한됩니다. 모델 확률이 배분의 중심이고, 다른 시간 영역을 찾는 효과는 작은 보정으로 남습니다. 같은 interval에 도달한 서로 다른 sequence의 확률 질량도 그대로 합칩니다.

BG-MCTS도 수식 reward를 사용할 수 있습니다. 다만 원래 선택식은 남은 예산에 따라 prior가 들어가는 탐색항을 약화시키므로, native 확률을 계속 중심에 두려면 선택식까지 조정해야 합니다. 우선은 DORA형 배분이 효과를 분리해 보기 쉽겠습니다. [BG-MCTS 선택식](https://arxiv.org/html/2602.09574v1)

비교 조건은 **LevinTS / 확률 질량만으로 배분 / 확률 질량＋작은 시간적 새로움 보정**으로 나누겠습니다. Entropy와 variance는 계속 측정하되, 높다는 이유만으로 높은 reward를 주지는 않겠습니다. 경계의 흔들림이나 극단적인 오답도 그 값을 키울 수 있기 때문입니다.

**Prefill은 많은 token을 병렬 처리하지만, 경로 탐색은 작은 forward를 수백~수천 번 반복하기 때문입니다.** Token 수 비율과 실행 시간 비율은 크게 다릅니다.

|---|---:|---:|

- **Prefill:** 이미 알려진 입력 전체를 큰 행렬 연산으로 처리해 GPU의 병렬 연산을 활용합니다.
- **Decoding:** 다음 token 분포를 얻을 때마다 모델의 모든 layer를 통과합니다. KV cache는 입력을 다시 계산하지 않게 해주지만, 새 token이 기존 영상·query의 KV를 참조하는 연산은 계속 필요합니다. 작은 batch의 decoding에서는 메모리 이동과 반복 호출 비용이 특히 중요합니다. [NVIDIA 설명](https://developer.nvidia.com/blog/mastering-llm-techniques-inference-optimization)
- **현재 구현:** prefix를 하나씩 처리하며 매 step 동기화와 CPU로의 확률 전달도 수행합니다. 이 부분에는 최적화 여지가 있습니다.

실제 탐색 25.70초를 나누면 **decoder forward 측정 구간 23.56초, KV 저장·복원 약 0.99초, 나머지 처리 약 1.15초**입니다. Forward 측정 구간에는 kernel 실행뿐 아니라 호출·대기 간격도 포함됩니다.
