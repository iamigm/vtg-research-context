2. **중복을 판단하는 단위**

   |---|---|---|
   | 같은 numeric interval | `[10, 20]`, `[10.0, 20.0]` | 하나의 답 후보로 합치고 생성 경로·출처는 보존 |

3. **어느 정도 가까우면 유사한 후보로 묶을지**

   IoU threshold, start/end 차이, interval 길이 대비 상대 오차 중 무엇을 사용할지 정해야 합니다. IoU만 사용하면 긴 interval에서는 큰 boundary 차이도 유사하게 처리될 수 있고, 절대 시간 차이만 사용하면 짧은 interval에서 중요한 차이를 합칠 수 있습니다.

   묶는 방식도 필요합니다. A–B와 B–C가 유사하지만 A–C는 다른 경우, 연결 관계만으로 모두 합칠지 결정해야 합니다. 저는 **exact interval만 우선 통합하고, 유사도 묶음은 다양성 관리에 사용하는 정책**을 권합니다. 유사도 threshold를 정할 때는 짧은 interval·긴 interval·인접한 반복 occurrence 사례를 함께 확인해야 합니다.

   - **최종 unique 후보가 하나:** 그 후보가 유효하면 추가 비교 없이 반환합니다.

## 2026-11-06T06:08:18.374Z — Codex final report

분기 기준으로 **“이 token을 선택하면, 이후 완성되는 interval의 분포가 어떻게 달라지는가”**를 쓰는 게 좋겠습니다. 원래 video·query prompt를 유지하고, token distribution에서 출발해 다른 시간 가설로 이어지는 경로를 찾는 방식입니다.

GT 없이 확인할 수 있는 것은 **모델이 여러 시간 가설에 확률을 배분하고 있는지, 어느 prefix에서 그 가설들이 갈리는지**입니다. 시간적으로 떨어진 가설을 실제로 다른 occurrence라고 확정하려면 영상 근거가 더 필요합니다. 우선 이를 `temporal mode`로 정의하고 탐색 대상으로 삼을 수 있습니다.

1. **Token entropy와 interval의 불확실성을 구분합니다**

   Token entropy가 높아도 소수점 이하 표기만 달라질 수 있습니다. 반대로 첫 숫자가 확실해도 그 뒤 `.`을 선택하는지, 다른 숫자를 이어 쓰는지에 따라 전혀 다른 시간대로 갈릴 수 있습니다.

   아래는 가상 예시입니다.

   | Continuation 결과 | 관측한 불확실성 | 탐색 방향 |
   |---|---|---|
   | `[12.0,18.0]`, `[12.1,18.0]`, `[11.9,18.2]` | 한 시간대 안의 boundary 차이 | boundary 대안으로 관리 |
   | `[12,18]`, `[104,111]` 주변에 각각 모임 | 분리된 temporal mode | 두 mode로 이어지는 분기 탐색 |
   | `[12,18]`, `[12,45]`, `[12,90]` | end·duration의 불확실성 | 긴 interval이 생기는 경로 검토 |
   | 시간대가 불규칙하게 흩어지고 parsing 실패가 많음 | 불안정한 생성 | 실패율과 mode 재현성 확인 |

   따라서 **완성 interval의 분포를 봐야 분기의 의미를 판단할 수 있습니다.** 서로 동등한 응답을 묶어서 불확실성을 측정하는 [Semantic Uncertainty](https://arxiv.org/abs/2302.09664)가 개념적 참고가 됩니다. 여기서 제안하는 temporal mode는 이번 실험을 위한 별도 정의입니다.

2. **분기 뒤를 여러 번 sampling해서 그 token의 영향을 봅니다**

   원래 prefix를 \(r\), 다음 token을 \(a\)라고 하면, 보고 싶은 것은 다음 분포입니다.

   \[
   P(\text{완성 interval}\mid r,a)
   \]

   진행 방식은 다음과 같습니다.

   - 원래 분포에서 소수의 stochastic rollout을 생성합니다.
   - 공유 prefix와 각 위치의 다음 token distribution을 저장합니다.
   - 관측된 대안 token 뒤에서 start/end가 완성될 때까지 conditional rollout을 추가합니다.
   - token별로 어느 temporal mode에 도달하는지 비교합니다.

   **각 대안 뒤를 greedy로 한 번만 완성하면 continuation의 여러 가능성을 놓칠 수 있습니다.** 추가 연산을 배정할 분기에서는 여러 stochastic continuation을 보는 것이 핵심입니다.

   첫 숫자뿐 아니라 정수 내부·소수점·separator·end 생성 과정까지 살펴봐야 합니다. start가 달라진 경로의 end는 새 start prefix를 조건으로 다시 생성합니다.

3. **‘어떤 token이 시간 가설을 가르는가’를 측정합니다**

   좋은 분기 위치는 다음 token에 따라 도달하는 temporal mode가 달라지는 위치입니다.

   예를 들어 한 prefix에서 다음처럼 관측됐다고 합시다.

   - token A 뒤에서는 대부분 이른 시간대 mode로 갑니다.
   - token B 뒤에서는 대부분 늦은 시간대 mode로 갑니다.

   이 위치는 occurrence 대안을 탐색하는 데 유용합니다. 반면 A와 B 뒤에서 모두 같은 시간대의 소수점 차이만 나온다면 새로운 시간대 탐색에는 기여가 작습니다.

   이를 정량화하는 후보는 **다음 token과 최종 temporal mode 사이의 mutual information**입니다.

   \[
   B(r)=I(A;C\mid r,\text{valid})
   \]

   \(A\)는 다음 token, \(C\)는 완성 interval의 mode입니다. 이 값은 유효한 continuation 안에서 **token 선택이 mode를 얼마나 구분하는지** 나타냅니다. Parsing 실패와 duration 위반의 확률은 별도로 기록합니다.

   다만 적은 rollout으로 계산한 값은 불안정합니다. 아직 충분히 관측하지 못한 분기에는 최소 탐색량을 주고, 표본이 늘어날 때 판단을 갱신해야 합니다.

- **Main sequence:** 각 분기에서 주요 token 집합을 따라간 경로

1. **주요 token 집합:** 누적 확률 질량 기준으로 확보할 token
2. **추가 조사 token 집합:** 주요 집합 밖이지만 확률 지지가 충분한 token
3. **제외 token 집합:** 지지가 너무 약해 분기하지 않을 token

핵심은 2번과 3번을 구분하는 기준입니다.

**최고 확률 token과의 상대 확률에 하한을 두겠습니다.**

현재 prefix에서 최고 token 확률이 \(p_{\max}\)라면, 추가 분기를 허용하는 조건을 다음처럼 잡는 정책안입니다.

\[
p(a\mid r)\ge \max\left(\tau_{\mathrm{abs}},\;\alpha p_{\max}\right)
\]

- \(\alpha\): 최고 token 대비 최소 확률 비율
- \(\tau_{\mathrm{abs}}\): 절대 확률의 최소값

최고 token의 확률에 비례해 하한을 정하는 부분은 [min-p sampling](https://proceedings.iclr.cc/paper_files/paper/2025/hash/afa5f124e36bed5cc2125067005d43f5-Abstract-Conference.html)의 아이디어를 참고할 수 있습니다. 여기에 절대 하한을 추가하는 것은 이번 실험을 위한 제안입니다.

예를 들어 **주요 질량 90%, \(\alpha=0.02\), 절대 하한 0.1%**를 출발점으로 잡으면 다음과 같습니다. 아직 검증된 최적값이라는 뜻은 아닙니다.

| Token | 원래 모델 확률 | 처리 |
|---|---:|---|
| A | 70% | 주요 token |
| B | 20% | 주요 token |
| C | 6% | 추가 조사 |
| D | 3% | 추가 조사 |
| E | 0.9% | 제외 |
| F | 0.1% | 제외 |

최고 확률이 70%이므로 상대 하한은 \(70\%\times0.02=1.4\%\)입니다.

따라서 A·B는 주요 분기로 확보하고, C·D도 조사합니다. E·F에서는 rollout을 열지 않습니다. **이 위치에서 C나 D를 거친 sequence는 tail로 기록**합니다.

여기에는 다음 원칙도 필요합니다.

- **원래 모델 확률로 판정합니다.** 숫자 token만 남긴 뒤 재정규화하거나 temperature를 높여서 작았던 확률을 키운 값으로 하한을 통과시키지 않습니다.
- **질량 목표를 채우려고 하한을 낮추지 않습니다.** 하한 때문에 확보한 질량이 목표에 미달하면 그 사실과 제외 질량을 기록합니다.
- **MI나 새로운 mode의 매력도가 하한을 무효화하지 않습니다.** 하한을 통과한 분기 안에서 MI와 \(S(r,a)\)로 추가 예산을 배정합니다.

이렇게 하면 모델이 한 token에 확신할 때는 분기가 적어지고, 여러 token을 실제로 지지할 때는 분기가 늘어납니다. 모델이 정말 0–9에 비슷한 확률을 주는 경우에는 여러 숫자가 모두 남을 수도 있습니다. 그때는 모델 자체가 여러 대안을 지지하는 상황입니다.

   | Offset fit | 사건의 끝을 놓치거나 불필요한 뒷부분을 포함하지 않았는가? |

   각 기준에 대해 `지지됨 / 반박됨 / 불확실함`을 선택하게 하고, 선택지 확률과 짧은 영상 근거를 기록합니다. 이 값들은 **정답 확률로 해석하거나 서로 곱하지 않습니다.**

   모델이 낮게 평가했다는 이유만으로 parent·siblings·mode 전체를 자동 삭제하지도 않습니다. 우선 상대 비교를 위한 판단과 진단값으로 사용합니다.

   **그다음 두 단계로 비교합니다.**

   - **같은 mode 내부:** 중앙 후보와 boundary 대안을 비교해, 같은 시간 가설에서 더 정확한 interval을 고릅니다.
   - **서로 다른 mode 사이:** mode별 winner를 모두 pairwise 비교해, query에 맞는 시간 가설을 고릅니다.

   비교 질문은 다음 순서를 명시합니다.

   > 먼저 요청한 사건과 occurrence가 맞는지 비교하라. 둘 다 맞는다면 onset과 offset이 더 정확한 interval을 선택하라. 근거가 부족하거나 동등하면 불확실/동률을 선택하라.

   각 pair는 A/B 순서를 바꿔 두 번 평가합니다. 후보가 최대 6개이므로 mode 간에는 최대 15쌍, 양쪽 순서로 30회 비교입니다. Knockout 대신 전체 pairwise 비교의 평균 선호 점수로 최종 후보를 고릅니다.

   순서를 바꾼 두 판단이 충돌하면 확신을 낮게 기록합니다. 최종 동률은 **main 확률 질량 → 고정된 interval 정렬 순서**로 해소합니다.

   **최종 답은 winner의 기존 clipped interval입니다.** 모델에게 timestamp를 다시 생성하게 하지는 않습니다. 후보 판단 단계의 별도 context에서 나온 확률도 원래 rollout probability와 섞지 않습니다.

6. **MI와 \(S\), 모델 판단의 역할 분담**

   세 값은 서로 다른 역할을 맡습니다.

   | 값 | 역할 |
   |---|---|
   | MI | 어떤 token 선택이 temporal mode를 가르는지 분석 |
   | \(S(r,a)\) | 추가 탐색 예산을 어느 경로에 쓸지 결정 |
   | 모델의 영상 판단 | 확보한 main 후보 중 query와 boundary가 맞는 답 선택 |

   이번 초기 실험에서는 **탐색 후 모델 판단** 순서로 둡니다. 판단 결과를 다시 탐색 prompt에 넣지는 않습니다. 이렇게 해야 후보 발견 방식의 효과와 feedback에 의한 분포 변화가 섞이지 않습니다.

   분기별 조사량이 다르므로 단순 생성 빈도를 mode 확률로 쓰지 않습니다. Raw probability와 실제 sampling probability를 모두 기록해 추정에 반영하고, 미탐색 질량과 추정 오차를 함께 표시합니다.

7. **예외 상황과 비교 실험**

   - 같은 sequence가 반복되면 sample 기록은 유지하고, 추론은 cache로 재사용합니다.
   - 같은 interval·mode가 반복되면 새 후보로 세지 않습니다.
   - 유효한 main interval이 하나면 추가 비교 없이 반환합니다.
   - 유효한 main interval이 없으면 실패로 기록합니다. Tail 후보로 대체하지 않습니다.
   - 모델 판단 예산이 부족하면 사전에 정한 중앙 후보를 반환하고 `judge_budget_fallback`으로 별도 표시하는 안입니다.
   - 모델이 후보들에 확신하지 못하면 그 상태를 기록하고, 고정된 상대 비교·동률 규칙으로 선택합니다.

   Probability 기준·token entropy 기준·temporal mode 기준의 세 탐색 조건에 **동일한 clipping·mode 규칙·후보 수·모델 판단 절차**를 적용합니다. Greedy도 같은 clipping으로 평가합니다.

   최종 성능뿐 아니라 **좋은 후보가 있었는지, shortlist에 들어갔는지, 모델이 선택했는지**를 단계별로 분해합니다. Tail에서만 발견한 좋은 mode는 진단 상한으로 분리해 보고합니다.

두 단계로 분리하면, **생성 단계의 목표를 “새 mode를 많이 찾기”에서 “검증기가 좋은 구간을 고르기 쉬운 후보 집합을 적은 비용으로 만들기”로 바꿔야 합니다.** 후보의 개별 품질과 함께, 어떤 후보들을 같이 제안하는지가 중요합니다.

| 총 rollout 상한 | 발견한 후보의 main oracle | 실제 제안한 대표 후보의 oracle | 최종 mIoU |
|---:|---:|---:|---:|
| 32 | 0.7132 | 0.6837 | 0.5266 |
| 256 | 0.7826 | 0.6880 | 0.5265 |

탐색을 늘려 좋은 구간은 더 찾았지만, **그 개선의 대부분이 대표 후보를 추리는 과정에서 사라졌고 최종 성능도 늘지 않았습니다.** 생성된 후보를 제안하는 방식부터 바꿀 필요가 있습니다.

우선 두 단계의 경계를 이렇게 잡겠습니다.

| 단계 | 역할 | 출력 |
|---|---|---|
| 후보 생성 | 경로 탐색, mode 구성, 경계 대안 정리, 제안할 후보 압축 | 작은 후보 집합과 생성 근거 |
| 검증·최종 답안 | 영상으로 후보를 검증하고 최종 구간 결정 | 최종 interval과 판단 근거 |

**대표 interval을 고르는 과정까지 생성 단계에 포함**해야 합니다. 그래야 “좋은 구간을 찾았는데 전달하지 못한 문제”와 “전달했는데 검증기가 고르지 못한 문제”를 분리할 수 있습니다.

제가 우선 시도할 방향은 다음 네 가지입니다.

**1. 새로운 mode 발견뿐 아니라, 유력한 mode의 경계를 더 확실하게 만드는 데 예산을 쓴다.**

현재 novelty 중심 배정은 이미 찾은 mode에서 더 좋은 interval이 나와도 새 mode 발견만큼 보상하지 않습니다. 그런데 최종 답을 개선하는 데 필요한 것이 새로운 사건이 아니라 **이미 유력하게 본 사건의 시작·끝을 바로잡는 것**일 수 있습니다.

예를 들어 여러 경로가 같은 발생 시점을 가리키지만 시작은 안정적이고 끝만 흔들린다면, 시작을 바꾸는 경로를 계속 찾기보다 **그 시작에 조건화한 끝 구간의 대안**을 조사하는 편이 합리적입니다.

생성 예산을 다음 두 용도로 나눕니다.

- **발생 시점 탐색:** 현재 후보와 다른 시간 가설이 있는지 확인.
- **경계 정밀화:** 지지가 있는 mode에서 시작·끝의 불확실성을 줄임.

경계 정밀화도 모델이 실제 생성한 joint interval을 사용해야 합니다. 서로 다른 응답의 시작과 끝을 임의로 조합하거나 평균내는 방식은 피하는 게 좋겠습니다.

**2. Sequence 하나의 확률보다, 같은 시간 가설에 모이는 지지를 본다.**

같은 interval이 여러 표현과 경로로 생성될 수 있습니다. 따라서 개별 sequence의 확률만 보면, 여러 경로에 지지가 분산된 유용한 mode를 낮게 평가할 수 있습니다.

각 mode에는 적어도 다음을 구분해 기록하겠습니다.

| 신호 | 알아보려는 것 |
|---|---|
| Mode에 모이는 모델 확률 질량의 추정 | 모델이 이 시간 가설을 얼마나 지지하는가 |
| 서로 다른 경로에서의 경계 일치 | 특정 경로 하나의 우연한 결과인가 |
| 시작·끝의 불확실성 | 어디를 더 조사하면 후보가 달라질 수 있는가 |
| 유효 interval로 끝나는 비율 | 연산을 쓰고도 후보를 얻지 못하는 분기인가 |

여기서 **많이 sampling됐다는 횟수를 모델 확률로 쓰면 안 됩니다.** Scheduler가 일부 분기를 집중 조사했기 때문입니다. 원래 확률과 sampling 확률을 구분하고, 관측한 질량이 전체 mode 질량의 일부라는 점도 유지해야 합니다.

다만 지지가 높다는 사실이 정답을 보장하지는 않습니다. 이 신호들은 후보 생성의 우선순위이며, 영상 근거에 의한 검증을 대신하지 않습니다.

**3. 후보를 추가할 때의 검증 비용과 혼동까지 고려한다.**

후보가 많으면 oracle은 높아지기 쉽지만, 검증기는 더 많은 비교를 해야 합니다. 현재 round robin에서는 mode 대표가 \(M\)개면 서로 다른 쌍이 \(M(M-1)/2\)개입니다. 순서를 바꿔 묻는 비용도 따라갑니다.

따라서 새 mode를 찾았다고 자동으로 제안하는 대신 이렇게 묻는 겁니다.

> 이 후보가 지금 후보 집합에 추가되면, 더 좋은 답을 고를 기회가 실제로 늘어나는가? 이미 있는 후보를 반복하거나 판단만 어렵게 하지는 않는가?

처음에는 **제안할 mode 수를 고정**하고 비교하는 것이 좋겠습니다. 각 mode에는 기본 대표 하나를 주고, 경계의 대안이 필요한 경우에만 두 번째 interval을 붙입니다. 약한 후보로 자리를 무조건 채울 필요도 없습니다.

이때 중요한 점은 **토큰 확률만으로 검증기의 선택 가능성을 정확히 알 수는 없다는 것**입니다. 원래 질문에 대한 생성 확률과, 후보들을 보여줬을 때 검증기가 선호하는 확률은 다른 분포입니다.

그래서 “선택되기 쉬워 보인다”는 생성 측 신호를 만들더라도, 그 효과는 **고정된 검증기**로 측정해야 합니다. 검증기까지 동시에 바꾸면 무엇이 개선됐는지 알 수 없습니다.

**4. 분기 score를 ‘새로움’에서 ‘후보 집합의 예상 개선량/추가 비용’으로 바꾼다.**

개념적인 목표는 다음과 같습니다.

\[
\text{분기 우선순위}
=
\frac{\text{그 분기를 조사해서 제안 후보 집합이 좋아질 예상량}}
{\text{추가 생성 비용}+\text{추가 검증 비용}}
\]

여기서 예상 개선은 두 종류입니다.

- 기존 후보가 설명하지 못하는, 지지 있는 다른 발생 시점을 찾는 것.
- 기존 유력 mode에서 더 안정적인 경계의 interval을 찾는 것.

반대로 같은 mode의 비슷한 interval만 반복해서 나오거나, 유효 응답을 잘 얻지 못하면 배정을 줄입니다. 이 목적이라면 MI는 보조 진단으로 남기고, **새 mode 수 자체를 직접 보상하는 비중을 낮추는 편**이 맞습니다.

중복 sequence의 재생성을 줄이는 방법도 검토할 수 있습니다. Sequence 단위 sampling without replacement의 한 방법으로 Stochastic Beam Search가 있습니다. 다만 서로 다른 sequence가 같은 mode로 이어지는 문제까지 해결하지는 않습니다. [공식 논문](https://proceedings.mlr.press/v97/kool19a.html)

마지막으로, **“선택될 가능성을 올린다”는 목표도 정확히 정의해야 합니다.** 아무 후보나 검증기가 강하게 선호하도록 만드는 것은 목적이 아닙니다. 우리가 원하는 것은 다음입니다.

> **좋은 후보를 제안했을 때, 그 후보가 실제 최종 답의 성공으로 이어지는 비율을 높인다.**

이를 평가할 때는 oracle 외에 다음을 함께 보겠습니다. GT는 모두 사후 평가에만 사용합니다.

- **제안 후보 oracle:** 생성 단계가 실제로 전달한 후보 안에 좋은 답이 있는가?
- **좋은 후보가 있을 때의 최종 성공 비율:** 예를 들어 제안 후보 중 IoU≥0.5가 있을 때, 최종 답도 IoU≥0.5가 되는가?
- **선택 손실:** 제안 후보 oracle − 최종 IoU.
- **전체 비용:** 후보 생성과 검증을 합쳐 얼마를 썼는가?

우선 실험은 **검증기를 고정하고, 후보 수를 맞춘 상태에서 현재 novelty 중심 생성과 ‘유력 mode의 경계 정밀화’를 함께 하는 생성을 비교**하는 것을 제안합니다. 이것이 oracle 증가가 실제 선택으로 이어지는지 가장 직접적으로 확인할 수 있는 첫 비교입니다.

그러면 목표를 **“모델이 지지하는 서로 다른 시간 구간을, 적은 연산으로 소수의 후보로 제안하기”**로 좁히겠습니다.

여기서 직접 다룰 수 있는 것은 **모델이 그 구간을 생성할 확률적 지지**입니다. 이것이 정답일 확률과 같지는 않습니다.

후보 생성은 다음처럼 구성하는 게 좋겠습니다.

1. **확률 질량이 큰 경로부터 조사한다.**  
   현재의 token 하한과 main 규칙을 유지하면서, 모델이 실제로 지지하는 경로를 우선 탐색합니다.

2. **같은 mode로 모이는 경로의 지지를 합친다.**  
   서로 다른 표현이 같은 시간 구간으로 이어진다면 하나의 후보에 대한 지지로 모읍니다. 반복 sampling 횟수와 원래 모델 확률은 구분합니다.

3. **새 mode 탐색과 기존 mode의 경계 정밀화에 예산을 나눈다.**  
   새로운 발생 시점을 찾는 것뿐 아니라, 유력한 mode 안에서 시작·끝이 더 안정적인 interval을 찾는 것도 탐색 성과로 봅니다. 예를 들어 시작은 일치하고 끝만 흔들린다면 끝에 관한 분기를 우선 조사합니다.

4. **고정된 K개 후보로 압축한다.**  
   지지가 높은 mode들을 포함하되 비슷한 구간으로 후보 자리를 채우지 않습니다. 대표 구간은 실제 생성된 interval 중에서 고릅니다.

분기 우선순위도 다음처럼 바꾸겠습니다.

> **추가 계산으로 후보 집합의 대표성이 얼마나 좋아질 것인가 / 추가 생성 비용**

여기서 대표성이 좋아진다는 것은 **지지 있는 다른 시간 가설을 추가하거나, 이미 지지 있는 가설의 경계를 더 잘 대표하게 되는 것**입니다. 새 mode라는 이유만으로 높은 점수를 주지는 않습니다.

평가도 후보 제안에 맞춰 세 가지로 제한하면 됩니다.

| 평가 | 확인할 것 |
|---|---|
| 고정 K에서의 oracle | 같은 후보 수로 더 좋은 구간을 포함하는가 |
| 모델 지지와 후보 다양성 | 낮은 확률의 대안을 늘려 oracle만 높인 것은 아닌가 |
| 생성 비용 | 같은 성능의 후보 집합을 더 적은 연산으로 만드는가 |

우선 비교할 핵심은 **현재의 새 mode 발견 중심 탐색**과 **확률 지지·경계 정밀화를 함께 고려하는 탐색**입니다. 후보 수 K와 생성 연산 예산을 맞춰 비교하겠습니다.
