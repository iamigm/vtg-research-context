## 2026-09-29T07:09:52.058Z — Codex final report

**영상 → 위치 추정 지시문 → 이벤트 query** 순서로, 하나의 user 메시지에 넣었습니다. 모델은 `Qwen3-VL-8B-Instruct`입니다.

예를 들어 Charades 샘플의 실제 입력 구조는 다음과 같습니다. 반복되는 영상 토큰만 축약했습니다.

```text
<|im_start|>user
<0.3 seconds><|vision_start|>[영상 토큰들]<|vision_end|>
<다음 timestamp><|vision_start|>[영상 토큰들]<|vision_end|>
...
Locate the segment where the following event happens.
Respond with start and end timestamps in seconds.
Event: person opening a box
<|im_end|>
<|im_start|>assistant
```

`[영상 토큰들]` 위치에는 샘플링한 프레임을 vision encoder로 처리한 임베딩이 들어갑니다. timestamp 문자열도 입력에 포함됩니다. **`<prefill>`, `<query>`라는 태그를 실제로 추가하지는 않았습니다.** MTLA의 원래 입력 형식을 유지했습니다.

| 데이터셋 | 영상 전처리 | 텍스트 지시문 |
|---|---|---|
| Charades-STA | 2 FPS, 최대 131,072 pixels | 위의 단일 구간 요청 |
| QVHighlights | 1 FPS, 최대 65,536 pixels | 해당 이벤트의 **모든 구간**을 `[start, end]` 목록으로 요청 |
| ActivityNet-Captions | 1 FPS, 최대 65,536 pixels | Charades와 같은 단일 구간 요청 |

Attention은 다음과 같이 읽었습니다.

- **query 행:** `Event:` 뒤의 이벤트 문장 토큰만 사용했습니다. 예시에서는 `person / opening / a / box`입니다.
- **관측 대상 열:** 앞에 있는 영상 patch 토큰입니다. timestamp 문자열이나 지시문에 향하는 attention은 시간별 곡선에서 제외했습니다.
- **정규화:** 전체 causal 입력에 대해 softmax한 뒤 영상 열을 선택했습니다. 영상 토큰끼리만 softmax한 것은 아닙니다.
- **실행:** 입력 전체를 한 번에 forward했습니다. 별도로 prefill KV cache를 만든 뒤 query를 추가하는 방식은 아니며, 응답도 생성하지 않았습니다.
- **GT:** 모델에 넣지 않고, 추출 후 그래프에만 표시했습니다.

- 인접 단계에서 증가한 비율은 데이터셋별 평균 **약 80~86%**입니다.
- 답변 토큰이 계속 추가되므로, 이 증가에는 **attention을 받을 이전 답변 토큰 수가 늘어나는 효과**도 포함됩니다. 이것만으로 영상보다 답변에 더 의존하게 됐다고 단정할 수는 없습니다.

`other prefix`는 **영상 patch 토큰과 이벤트 query 문장을 제외한 나머지 입력 토큰 전체**입니다. 실제 입력의 대표 예시는 다음과 같습니다.

| 종류 | 실제 예시 |
|---|---|
| 위치 추정 지시문 | `Locate the segment where the following event happens.` |
| 출력 형식 지시문 | `Respond with start and end timestamps in seconds.` |
| 이벤트 문장 앞 표지 | `Event:` |
| 프레임 시간 텍스트 | `<0.3 seconds>`, `<1.3 seconds>` |
| 영상 경계 토큰 | `<\|vision_start\|>`, `<\|vision_end\|>` |
| 대화 형식·답변 시작 부분 | `<\|im_start\|>user`, `<\|im_end\|>`, `<\|im_start\|>assistant` 및 줄바꿈 |

특히 **프레임 timestamp 텍스트도 현재 집계에서는 `video`가 아니라 `other prefix`**입니다. 따라서 이 그룹을 단순히 “영상과 무관한 토큰”으로 해석하면 안 됩니다. 현재 합산 결과만으로는 그 안에서 **시간 텍스트·지시문·특수 토큰 중 무엇에 attention이 집중되는지**는 구분되지 않습니다.
