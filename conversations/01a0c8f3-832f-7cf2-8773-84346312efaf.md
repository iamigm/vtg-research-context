- 입력 100만 토큰: **$0.25**
- 캐시된 입력 100만 토큰: **$0.025**
- 출력 100만 토큰: **$2.00**

**현재 GPT API 호출은 시작하지 않았으므로 해당 API 비용은 발생하지 않았습니다.** 유료 API가 필요하다는 점을 먼저 명확히 설명했어야 했습니다.

## 2026-09-23T04:35:51.688Z — Codex final report

**코드에서는 로컬에서 동영상을 10초 단위로 나누고, 각 구간의 프레임 이미지와 전사 텍스트를 GPT에 전달합니다.** 동영상 파일 전체를 첨부하는 방식은 아닙니다.

Video-MME용 공개 코드의 흐름은 다음과 같습니다.

1. **10초 구간마다 약 10장의 프레임 추출**
   `decord`로 영상을 읽고 매초 한 장씩 뽑습니다. 예를 들어 `[20초, 30초)` 구간이면 20, 21, …, 29초 프레임을 사용합니다. [프레임 추출 코드](/home/irteam/WorldMM/preprocess/episodic_memory/generate_fine_caption.py:226)

2. **프레임 시각과 해당 구간의 transcript를 함께 구성**
   한 번의 요청에 구간 시작·종료 시각, 겹치는 SRT 전사 문장, 시간순 이미지와 각 이미지의 timestamp가 들어갑니다. **원본 오디오 자체는 전달하지 않습니다.** 각 구간은 독립적으로 caption을 생성합니다. [프롬프트 구성 코드](/home/irteam/WorldMM/preprocess/episodic_memory/generate_fine_caption.py:283)

3. **이미지를 압축해 API로 전송**
   이 경로에서는 각 이미지의 종횡비를 유지하면서 **최대 512×512**로 축소하고, JPEG 품질 85로 인코딩합니다. 이를 Base64 `input_image`로 바꿔 `responses.create()`에 전달합니다. [이미지 처리 코드](/home/irteam/WorldMM/src/worldmm/llm/openai_gpt.py:355), [API 호출 코드](/home/irteam/WorldMM/src/worldmm/llm/openai_gpt.py:645)

4. **10초 caption을 계층적으로 요약**
   이후 `10초 → 30초 → 3분 → 10분` caption은 앞 단계의 **텍스트를 요약**해서 만듭니다. 이 단계에서는 영상을 다시 보지 않습니다. [다중 시간 단위 요약 코드](/home/irteam/WorldMM/src/worldmm/memory/episodic/gen_multiscale.py:316)

따라서 **GPT에 도달하기 전의 샘플링·해상도·압축·입력 구성은 코드로 확인할 수 있습니다.** 서버 측 이미지 토큰 계산 규칙도 일부 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/images-vision)에 공개돼 있습니다. 다만 GPT 내부의 시각 인코더와 여러 이미지·텍스트를 통합하는 정확한 연산은 이 코드와 API 응답으로 확인할 수 없습니다.

Failure mode 분석에서는 이 구분이 중요합니다. **1 FPS 사이에 지나간 동작, 축소하면서 읽기 어려워진 글자, 10초 경계를 걸치는 사건, 요약 중 사라진 세부 정보**는 입력·메모리 단계에서 조사할 수 있는 실패 후보입니다. 이를 모두 GPT 내부의 불투명성으로 돌릴 필요는 없습니다.

참고로 현재 새 실험은 저자가 제공한 **10초 caption을 재사용**하도록 구성했습니다. 지금 필요한 GPT 호출은 그 이후의 다중 시간 단위 요약과 메모리 구축 등에 해당합니다.
