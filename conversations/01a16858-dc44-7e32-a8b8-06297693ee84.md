**결과 뷰어용으로 저장한 영상이 가장 큰 원인입니다.** 실제 사용량은 약 **94.4GiB**이고, MP4 영상만 **60.5GiB로 약 64%**입니다.

하드링크 중복을 제외한 주요 용량은 다음과 같습니다.

| 항목 | 용량 | 내용 |
|---|---:|---|
| 전체 벤치마크 `timelens_top30_full/media` | 55.9GiB | 추가로 생성된 영상 |
| 기존 `timelens_top30/media` | 4.4GiB | 초기 실험 영상 |
| `timelens_rollout/records` | 9.9GiB | rollout JSON 6,000개 |
| `attention/results` | 14.1GiB | attention 배열·시각화 등 |
| `zero-shot/predictions` | 5.7GiB | 예측 TXT·JSON |
| 공유 실행 환경 및 기타 | 4.4GiB | 라이브러리·나머지 결과 |

영상이 큰 이유는 [영상 생성 코드](/home/irteam/experiments/zero-shot/_lib/timelens_top30_media.py:15)가 **원본 영상 전체를 해상도·길이 축소 없이** 브라우저용 MP4로 따로 저장하기 때문입니다. H.264 영상은 영상 스트림을 그대로 복사하고, 다른 코덱은 H.264로 변환합니다. 전체 벤치마크 영상 폴더에는 **4,279개**가 있습니다.

일부 영상과 결과는 이미 하드링크로 공유하고 있어, 여러 폴더에 보이는 같은 파일이 매번 용량을 추가하는 것은 아닙니다. 용량을 줄이려면 **뷰어용 영상의 보관 범위나 해상도**를 조정하는 것이 가장 효과적입니다. 파일은 변경하거나 삭제하지 않았습니다.

## 2026-10-23T10:44:39.898Z — Codex final report

**초기 300개 샘플 실험용인지, 전체 벤치마크 실험용인지의 차이입니다.** 영상 포맷과 생성 방식은 같습니다.

| | `timelens_top30/media` | `timelens_top30_full/media` |
|---|---:|---:|
| 실험 범위 | 초기 300개 샘플 | 전체 9,404개 샘플 |
| 고유 영상 수 | 292개 | 4,279개 |
| 영상 용량 | 약 4.4GiB | 약 60.3GiB, 기존 영상 포함 |

한 영상에 여러 질문이 있어서 샘플 수보다 영상 수가 적습니다.

`full/media`는 기존 292개를 **전부 하드링크로 공유**하고, 새로운 영상 3,987개를 추가한 구조입니다. 따라서 앞서 말한 **55.9GiB는 `full`에서 추가로 차지하는 용량**이고, 폴더 전체 영상은 약 60.3GiB입니다.

즉, `top30/media`만 삭제해도 공유 영상이 `full/media`에 남아 있으므로 **4.4GiB가 확보되지는 않습니다.**
