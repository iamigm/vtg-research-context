**가능합니다. 기존 Qwen3-VL-8B-Instruct를 유지하고, TimeLens 공식 평가 코드에서 입력 블록 순서만 바꾸면 됩니다.** 다만 기존 `query→video attention` 지표는 두 조건에 그대로 적용할 수 없습니다.

공식 코드(`5d2110f`)는 하나의 user 메시지에 `[video, text]`를 넣습니다. `apply_chat_template()` 직전에 다음 한 줄을 추가하면 반대 순서가 됩니다.

```python
messages[0]["content"].reverse()  # [video, text] → [text, video]
```

여기서 `text`는 **이벤트 문장과 공식 지시문을 포함한 전체 프롬프트**입니다. 이 블록 전체를 옮겨야 문구를 유지하면서 순서만 비교할 수 있습니다. 영상 프레임과 timestamp의 내부 순서는 그대로입니다. [공식 입력 구성 코드](https://github.com/TencentARC/TimeLens/blob/5d2110fb3faf74f4b0fc5957cd7ab73bea4763dc/evaluation/utils.py#L52-L103)

실제로 세 벤치마크에서 각각 한 샘플씩 CPU 전처리를 실행해 확인했습니다.

- 영상 입력 텐서와 `video_grid_thw`: 두 순서에서 **bitwise 동일**
- 프롬프트 토큰과 전체 입력 길이: 동일
- 최종 `input_ids`: **video/text 블록 위치만 정확히 교환됨**

TimeLens 데이터도 로컬에 모두 있습니다. 공식 로더로 확인한 수량이며, 참조하는 영상 파일의 누락은 없습니다.

| 교체할 벤치마크 | 평가 query 수 |
|---|---:|
| Charades-TimeLens | 3,363 |
| ActivityNet-TimeLens | 4,500 |
| QVHighlights-TimeLens | 1,541 |

이들은 수정된 query와 GT를 사용하는 별도 평가셋이므로, 기존 300개 목록 대신 공식 TimeLens annotation에서 입력 목록을 구성해야 합니다. [공식 데이터 로더](https://github.com/TencentARC/TimeLens/blob/5d2110fb3faf74f4b0fc5957cd7ab73bea4763dc/timelens/dataset/timelens_data.py)

공식 평가를 따르려면 두 순서 모두 다음 조건을 같게 유지해야 합니다.

- 공식 실행 셸 기준 `fps=2`, `min_tokens=64`, `total_tokens=14336`
- BF16, FlashAttention 2, `do_resize=False`
- greedy 생성, `max_new_tokens=512`
- 공식 timestamp 파싱·초 단위 반올림·첫 번째 예측 구간 평가

Python 평가 파일을 직접 실행하면 토큰 예산 기본값이 셸과 다르므로 **셸의 값을 명시적으로 전달해야 합니다.** 모델 경로도 셸 기본값인 TimeLens-8B 대신 기존 Qwen3-VL-8B-Instruct를 지정해야 합니다. [실행 설정](https://github.com/TencentARC/TimeLens/blob/5d2110fb3faf74f4b0fc5957cd7ab73bea4763dc/scripts/eval_timelens_bench.sh), [추론 코드](https://github.com/TencentARC/TimeLens/blob/5d2110fb3faf74f4b0fc5957cd7ab73bea4763dc/evaluation/eval_dataloader.py)

**attention 비교에서는 causal mask가 핵심입니다.**

| 입력 순서 | 입력 query가 영상에 attention을 보낼 수 있는가? |
|---|---|
| `video → query → answer` | 가능 |
| `query → video → answer` | 불가능: 영상이 미래 토큰이므로 차단 |

따라서 grounding 성능은 그대로 비교할 수 있지만, 공통 attention 비교 대상으로는 **두 조건 모두 영상 뒤에 있는 답변 생성 행의 `answer→video attention`**이 적절합니다. 현재 [입력 처리 코드](/home/irteam/experiments/mtla_attention/_lib/input_pipeline.py:105)도 영상이 query보다 앞선다고 가정하므로 수정이 필요합니다.

이번에는 코드 조사와 CPU 입력 검증까지 진행했습니다. 검증 환경은 기존 Transformers 4.57.6이며, 본 실험에서는 공식 지정 버전인 4.57.1에 맞추는 것이 필요합니다.

## 2026-10-20T06:29:52.347Z — Codex final report

**MTLA는 Multi-Token Localized Attention**의 약자이며, 다음 논문에서 제안한 방법입니다.

[**Propose and Attend: Training-free MLLM Grounding Confidence via Multi-Token Localized Attention**](https://arxiv.org/abs/2607.05978)  
Daniel Shalam 외, 2026년 7월 공개.

핵심은 **모델이 생성한 위치·시간 구간을 설명하는 토큰들이, 자신이 예측한 영역에 얼마나 attention을 주는지**로 예측 신뢰도를 계산하는 것입니다. 여러 예측 토큰의 attention을 합쳐 점수화하고, 추가 학습 없이 후보 재정렬에 사용합니다.

현재 폴더의 `MTLA/`는 이 논문의 [공식 코드](https://github.com/TalRemez/MTLA)입니다. 다만 지금 진행한 **TimeLens 입력 순서 비교는 별도의 실험**이고, 정답 구간의 attention 비중을 측정한 값도 논문의 ‘예측 영역 기반 MTLA 신뢰도’와는 구분해야 합니다.
