## 2026-10-08T08:09:19.280Z — Codex final report

응. 네 가설을 검증하려면 **“무슨 일이 일어났는지 아는가 → 그 사건을 영상 내 다른 사건과 구별하는가 → 해당 위치를 timestamp로 표현하는가”**를 나눠 보는 게 좋아. Captioning은 잘하고 temporal grounding은 못한다는 결과만으로 modality gap을 특정할 수는 없지만, **의미 이해 이후 어느 단계에서 성능이 무너지는지**는 확인할 수 있어.

내 추천은 **동일한 영상 입력으로 captioning과 grounding을 비교하는 실험을 중심에 두고, 짧게 잘라서 하는 captioning은 원인 분석용으로 추가하는 것**이야. 아래 수치들은 논문에서 정해진 표준이 아니라, 시작하기 위한 실험 설정 제안이야.

**Sampling은 입력 FPS와 caption을 만드는 시간 단위를 따로 정해야 해.**

| 변수 | 의미 | 첫 실험 제안 |
|---|---|---|
| 입력 FPS | 모델이 실제로 보는 시간적 정보량 | 2 FPS에서 시작, 0.5·1·2·4 FPS 비교 |
| Caption window | 한 caption이 설명하는 구간 길이 | 4초에서 시작, 2·4·8초 비교 |
| Caption stride | 다음 caption을 만들기 위해 이동하는 간격 | Window 길이의 절반 |

예컨대 `2 FPS, 4초 window, 2초 stride`면 8개 프레임으로 각 구간을 설명하는 셈이야. Overlap은 사건이 window 경계에서 잘리는 영향을 줄이려는 목적이고.

다만 **모든 영상을 같은 FPS로 처리하는 것보다, 관심 사건의 길이를 먼저 보는 게 중요해.** 0.5초짜리 동작과 20초짜리 요리 단계는 요구하는 해상도가 다르니까. 짧은 핵심 동작이 많으면 8 FPS 조건도 필요하고, 예산이 작으면 일부 샘플에서 먼저 FPS를 올려가며 semantic score가 더 이상 크게 오르지 않는 지점을 찾으면 돼. 단순히 프레임 수가 충분하다고 동작 정보가 보존되는 건 아니므로 실제 점수로 확인해야 해.

실험할 때 특히 두 가지를 통제해야 해.

- **같은 FPS 조건 안에서는 captioning과 grounding에 정확히 같은 프레임을 제공하기.** Captioning에만 더 많은 프레임을 주면 비교가 어려워져.
- **FPS를 올렸는데 모델의 최대 프레임 수 제한 때문에 영상 일부가 잘리는지 확인하기.** 실제 입력 프레임 수·시각·영상 커버리지를 기록해야 해.

처음부터 모든 조합을 돌릴 필요는 없어. Window를 4초로 고정하고 FPS를 먼저 비교한 뒤, 선택한 FPS에서 window 길이를 비교하면 돼.

**Caption이 의미적으로 잘 grounded됐는지는 “맞는 말을 했는가”와 “필요한 사건을 설명했는가”를 함께 봐야 해.**

“사람이 주방에서 요리한다”는 틀리지 않았어도, “양파를 썰다가 그릇에 옮긴다”를 이해했다는 증거는 부족해. 그래서 문장 전체에 대한 유사도 하나보다 **사건을 작은 사실로 분해해서 평가하는 방식**을 추천해.

예를 들어 GT가 “빨간 컵을 집어 물을 따른 뒤 내려놓는다”라면:

| 평가 요소 | 확인할 내용 |
|---|---|
| 대상과 속성 | 컵인지, 빨간 컵인지 |
| 동작과 관계 | 집는지, 컵에 물을 따르는지 |
| 상태 변화 | 물이 없는 상태에서 담긴 상태로 변하는지 |
| 순서 | 집기 → 따르기 → 내려놓기인지 |

여기서 두 점수를 따로 계산해.

- **Semantic precision:** 생성한 사실 중 영상으로 확인되는 사실의 비율.
- **Event recall:** 사전에 정한 핵심 사건·사실 중 caption이 정확히 설명한 비율.

Precision만 높으면 두루뭉술한 caption이 유리하고, recall만 높으면 이것저것 추측해서 나열하는 caption이 유리해져. 두 점수를 함께 봐야 “의미를 정확히 안다”는 주장을 할 수 있어. GT caption에 없다는 이유만으로 틀렸다고 처리하지 말고, 추가로 언급한 사실은 영상에서 확인해야 하고.

평가는 작은 파일럿에서는 사람이 직접 하는 게 가장 명확해. 규모를 늘릴 때는 **모델 입력 조건을 가린 독립적인 judge**로 사실별 판정을 하고, 사람이 검수한 표본에서 일치도를 확인하면 돼. 생성한 모델의 자기평가만으로 결론 내리는 건 피하는 게 좋겠어.

추가로 **같은 영상 안의 헷갈리는 사건을 구별하는지**를 꼭 보자. 예를 들어 “컵을 집는다/내려놓는다”, “문을 연다/닫는다”, “붓기 전/후”를 바꾼 caption 중 올바른 것을 선택하게 하는 거야. 자유 생성에서 빠뜨린 것과 실제로 구별하지 못하는 것을 분리할 수 있어. 이런 접근은 정적 내용은 같지만 시간적 특성이 다른 영상으로 평가하는 [TempCompass](https://arxiv.org/abs/2403.00476), 동작·순서 등의 오류를 평가하는 [VidHalluc](https://arxiv.org/abs/2412.03735)와도 연결돼.

**네 가설을 직접 검증하는 비교는 이렇게 구성하면 좋겠어.**

| 조건 | 모델에 시키는 일 | 주로 확인하는 것 |
|---|---|---|
| A. 전체 영상 captioning | Timestamp 없이 관찰한 사건들을 구체적으로 기술 | 전체 영상에서 사건 의미를 포착하는가 |
| B. 전체 영상 grounding | 별도 실행에서 GT 사건 설명을 주고 시작·종료 시각 출력 | 같은 입력에서 해당 사건을 찾는가 |
| C. 고정 window captioning | 외부에서 자른 각 window를 설명 | 국소적으로 보면 의미를 인식하는가 |
| D. 구간 선택 | B와 같은 영상에서 사건에 해당하는 bin/frame ID 선택 | 숫자 시각 생성 부담을 줄이면 나아지는가 |
| E. 텍스트 기반 구간 선택 | 검증된 window별 설명과 ID를 주고 해당 ID 선택 | 시각 입력을 텍스트로 바꾸면 나아지는가 |

A에는 너무 짧은 요약을 요구하지 말고, 주요 동작과 상태 변화를 충분히 기술하게 해야 해. 그리고 **A의 caption에서 사건을 의미적으로 맞게 기술했는지 평가할 때는 timestamp나 시간적 겹침을 사용하지 않아야 해.** 그 단계부터 temporal IoU를 섞으면 분리하려던 두 능력을 다시 합치게 되니까. 시간적 정합성과 caption 품질을 함께 다루는 [SODA](https://www.ecva.net/papers/eccv_2020/papers_ECCV/html/6406_ECCV_2020_paper.php) 같은 지표는 최종 시스템 평가에는 쓸 수 있지만, 이번 진단의 주지표로는 분리된 점수가 더 적합해.

C는 특히 해석에 주의해야 해. **짧게 잘랐더니 captioning이 잘된다는 결과는, 전체 영상에서도 그 사건을 잘 이해했다는 증거가 아니야.** 외부에서 잘라주면서 사건 탐색과 긴 문맥 처리 부담을 이미 줄여준 결과니까. GT 구간만 잘라 captioning하는 조건도 추가할 수 있지만, 이것 역시 보조 진단으로 봐야 해.

D에서는 선택한 ID를 코드로 timestamp에 변환하고 B와 비교하면 돼. 단, 거친 bin을 고르는 것은 정밀한 경계를 생성하는 것보다 쉬우니, **B의 출력도 같은 bin 해상도로 환산해서 비교**해야 공정해.

**가장 보고 싶은 결과는 “caption에서 맞게 설명한 사건인데 grounding은 실패한 비율”이야.**

사건별로 A의 의미적 성공 여부와 B의 grounding 성공 여부를 짝지어서 다음을 보면 돼.

\[
P(\text{grounding 실패}\mid\text{caption에서 사건을 정확히 설명})
\]

Grounding은 tIoU 기준 성공률과 시작·종료 경계의 오차를 같이 보고, 위 조건부 실패율도 별도로 보고하면 돼. 반복 사건은 같은 동작을 여러 번 하므로, 처음에는 한 번만 등장하는 사건으로 진단하고 반복 사건을 별도 묶음으로 보는 게 해석하기 편해.

결과는 이렇게 읽을 수 있어.

- **FPS를 올리자 둘 다 개선:** 입력에서 사건 정보가 부족했을 가능성.
- **Window caption은 잘하지만 전체 caption은 못함:** 긴 문맥에서의 정보 보존·탐색 문제가 후보.
- **전체 caption과 ID 선택은 잘하지만 timestamp는 못함:** 시간 좌표 매핑·경계 정밀도·출력 형식 문제가 후보.
- **텍스트 기반 ID 선택은 잘하지만 영상 기반 ID 선택은 못함:** 시각 정보의 표현·접근·정렬 문제가 후보. 다만 텍스트화가 사건 분할과 정보 압축까지 도와주므로 이것만으로 modality gap의 인과적 증거가 되지는 않아.

나는 **100~200개 영상의 파일럿에서 2 FPS로 A/B를 먼저 짝지어 평가하고, 같은 프레임에서 C를 만든 뒤, 의미는 맞고 시간이 틀린 사례에 D/E를 추가**하겠어. 이후 대표 표본에서 FPS를 바꿔보면 돼. 이렇게 하면 네 직감인 “무슨 일인지는 아는데 언제인지는 모른다”가 실제로 성립하는지부터 확인하고, 그 차이가 어디에서 발생하는지 좁혀갈 수 있어.

## 2026-10-08T08:14:17.007Z — Codex final report

응. 그러면 우선 **“GT 구간을 정확히 보여줬을 때, query에 해당하는 내용을 스스로 설명하는가?”**만 보자. Timestamp 예측은 빼고, 아래처럼 진행하겠어.

`GT 구간 전체 → query 없이 caption 생성 → caption과 query의 의미 대응 평가`

**1. 먼저 Charades-STA test의 모든 GT 구간으로 시작**

로컬 annotation을 확인했는데, 첫 실험에는 Charades-STA가 다루기 편해.

| 데이터 | Query 수 | GT 구간 수 | 구간 길이 중앙값 |
|---|---:|---:|---:|
| Charades-STA test | 3,720 | 3,720 | 7.1초 |
| ActivityNet val_1 | 17,505 | 17,505 | 22.89초 |
| QVHighlights val | 1,550 | 2,803 | 16초 |

Charades는 query당 GT 구간이 하나이고, 가장 긴 구간도 약 24.3초라 전체 구간을 충분히 보여주기 쉬워. QVHighlights는 여러 GT 구간에 걸친 query의 평가 방식을 추가로 정해야 해.

**2. GT 구간 전체를 2 FPS로 보고, 구간당 caption 하나 생성**

여기서는 sliding window로 다시 나누지 않고, **각 GT의 `[start, end)` 전체를 하나의 입력**으로 사용하겠어.

- 기본 2 FPS, 아주 짧은 구간은 최소 8개 프레임을 균등 추출.
- 실제 추출한 프레임 시각과 개수를 저장.
- Query와 원본 timestamp는 caption 모델에 주지 않음.
- 우선 시각 입력만 사용.
- 이후 grounding을 평가할 때 사용할 것과 같은 모델을 사용.

Caption prompt는 짧은 요약보다 **관찰한 동작을 빠뜨리지 않고 구체적으로 기술**하도록 잡겠어.

> Describe the observable events throughout this clip in chronological order. Include the actors, actions, objects they interact with, and visible state changes. Describe all distinct actions concisely. Avoid speculation. Do not include timestamps.

Query를 주면 모델이 query 내용을 따라 쓰는 효과가 생기니, 생성 단계에서는 완전히 분리해야 해.

**3. 점수는 대칭적인 문장 유사도보다 “caption이 query를 얼마나 뒷받침하는가”로 평가**

GT 구간에는 query 외의 행동도 있을 수 있어. 따라서 caption이 더 상세하다는 이유로 감점하지 않고, **query의 핵심 의미가 caption에 들어 있는지**를 보겠어.

예를 들어 query가 `person turns a light on`일 때:

| 생성 caption | 판정 |
|---|---|
| 사람이 스위치를 누르자 불이 켜진다 | 충족 |
| 사람이 스위치 근처에서 손을 움직인다 | 부분적으로 충족 |
| 사람이 방 안에 서 있다 | 미언급 |
| 사람이 불을 끈다 | 모순 |

별도 text judge에 query와 caption만 주고, query를 **주체·동작·대상·상태 변화·필요한 순서** 등의 사실로 분해한 다음 각 사실을 다음처럼 판정하게 하겠어.

`충족 / 부분 충족 / 미언급 / 모순`

각 판정에는 **caption의 근거 구절**도 함께 출력하게 해. “미언급”과 “모순”을 분리하는 게 중요해. Caption에서 빠졌다는 사실만으로 모델이 그 사건을 이해하지 못했다고 단정할 수는 없으니까.

주지표는 세 가지면 충분해.

- **완전 대응률:** Query의 모든 핵심 사실을 caption이 뒷받침한 샘플 비율.
- **핵심 사실 coverage:** Query의 핵심 사실 중 완전히 충족된 비율.
- **모순 발생률:** Query의 핵심 사실과 반대되는 내용을 기술한 샘플 비율.

Embedding cosine similarity는 보조로 저장할 수 있지만, 주지표는 위 판정으로 잡겠어.

**4. 낮은 점수의 원인을 영상으로 확인**

Text judge가 측정하는 것은 **query–caption 대응도**야. Caption의 시각적 정확성까지 보장하지는 않아. 그래서 점수별로 표본을 뽑아 사람이 GT 영상을 보며 다음을 구분해야 해.

[논문](https://arxiv.org/abs/2607.17423) · [공식 코드](https://github.com/MCG-NJU/TimeLens2) · [체크포인트](https://huggingface.co/MCG-NJU/TimeLens2-8B)

학습·평가 코드뿐 아니라 **SFT까지만 수행한 체크포인트와 SFT+GRPO 최종 체크포인트가 모두 공개**되어 있어. 그래서 같은 논문 안에서 아래 세 가지를 비교할 수 있어. [공개 모델 목록](https://github.com/MCG-NJU/TimeLens2#models-and-data)

| 비교 대상 | 현재 baseline 이후 추가 학습 | 확인할 차이 |
|---|---|---|
| Qwen3-VL-8B-Instruct | 없음: 현재 zero-shot | 기본 grounding 능력 |
| TimeLens2-8B-SFT | 영상·query → GT 시간 구간을 지도학습 | Grounding supervision의 효과 |
| TimeLens2-8B | SFT 이후 GRPO | 시간 구간에 직접 보상을 주는 학습의 추가 효과 |

**방법상의 핵심은 시간 구간 자체를 학습 목표로 삼는다는 점이야.** SFT에는 TimeLens2-93K, TimeLens-100K, Ego4D-NLQ 학습 데이터를 사용해. 이후 GRPO에서는 tIoU와 temporal Wasserstein 보상을 함께 사용해. 예측이 GT와 겹치지 않아 IoU가 모두 0이더라도, GT에 가까운 예측과 멀리 떨어진 예측을 구분해 학습시키는 방식이야. 논문에 따르면 두 단계 모두 visual encoder를 고정하고 언어 모델을 업데이트해. [학습 방법](https://arxiv.org/html/2607.17423v1#S4.SS1)

우리 실험에는 이렇게 붙이는 게 좋아.

1. **기존 pilot 100개에서 세 체크포인트의 MR을 비교.** 프레임·해상도·prompt·생성 설정·timestamp 평가 방식을 동일하게 맞춰.
2. **현재 Qwen3 caption이 query를 충족한 샘플 집합을 고정**하고, SFT와 GRPO 이후 MR 실패가 얼마나 줄어드는지 확인해. 모델마다 조건부 평가 대상을 바꾸지 않는 게 핵심이야.
3. 각 체크포인트에도 **GT-only captioning을 독립적으로 수행**해서, caption 대응 자체가 달라졌는지도 함께 확인해.
4. 모든 비교에서 **IoU 0.3·0.5·0.7, mIoU, 성공으로 바뀐 사례와 실패로 바뀐 사례**를 기록해.

전처리는 주의해야 해. **TimeLens2 논문의 Charades 평가는 4 FPS**라서, 논문 수치를 현재 2 FPS 실험 옆에 그대로 놓으면 조건이 달라. 먼저 세 모델 모두 **현재의 통일된 2 FPS 설정**으로 비교하고, 논문 설정 재현은 별도 실험으로 구분하는 게 맞아. [공식 평가 설정](https://arxiv.org/html/2607.17423v1#A1.SS4)

이 비교는 네 질문을 **“caption으로 이미 표현되는 사건에 대해, grounding 전용 학습이 시간 위치 예측을 얼마나 개선하는가?”**로 구체화해 줄 수 있어. 다만 개선이 관찰돼도 그것만으로 modality gap이 원인이라고 확정할 수는 없어.
