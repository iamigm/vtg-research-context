MTLA의 moment retrieval은 **Qwen3-VL이 시간 구간을 텍스트로 생성하고, 그 구간 내부의 비디오 토큰에 대한 attention으로 신뢰도를 계산한 뒤, 여러 생성 결과를 재정렬하는 방식**입니다. 공식 구현은 `generate → extract → evaluate`의 세 단계로 나뉩니다. [공식 저장소](https://github.com/TalRemez/MTLA)

아래는 로컬 `/home/irteam/vtg_works/MTLA`의 **커밋 `c6379bb`** 기준입니다. 프레임 처리까지 확인하기 위해 저장소가 지정한 `qwen-vl-utils==0.0.14`, `transformers==4.57.6`의 설치 코드도 읽었습니다. 모델 추론을 새로 실행한 결과가 아니라 **실제 코드 경로를 분석한 설명**입니다.

전체 흐름은 다음과 같습니다.

```text
비디오 + 자연어 query
  → FPS 기준 균일 프레임 샘플링
  → 비디오 토큰 + instruction/query 입력
  → Qwen3-VL이 [start, end] 텍스트 생성
  → 생성 답변을 붙여 teacher-forcing forward
  → 시간 숫자 토큰 → 예측 구간 내부 비디오 토큰 attention 추출
  → attention 신뢰도로 후보 선택/NMS
  → 최종 시간 구간 및 평가 점수
```

먼저 **프레임 샘플링은 데이터셋별 FPS 설정에 따라 달라집니다.**

| 항목 | QVHighlights | Charades-STA |
|---|---:|---:|
| 모델 | Qwen3-VL-8B-Instruct | 동일 |
| 목표 샘플링 FPS | 1 FPS | 2 FPS |
| 프레임당 `min_pixels` | 4,096 | 4,096 |
| 프레임당 `max_pixels` | 65,536 | 131,072 |
| 기대 답변 | 여러 시간 구간 | 한 시간 구간 |
| 최대 생성 토큰 | 128 | 128 |
| 최대 모델 시퀀스 길이 | 32,768 | 32,768 |

MTLA가 직접 프레임 인덱스를 계산하지는 않습니다. `_video_message()`에 FPS와 픽셀 예산을 넣고, `process_vision_info()`에 샘플링을 맡깁니다. 비디오의 시작·종료 crop은 별도로 지정하지 않으므로 **제공된 비디오 파일 전체에서 샘플링**합니다. [호출 코드](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:427)

라이브러리의 실제 계산은 다음과 같습니다.

```python
# F: 원본 프레임 수, original_fps: 원본 FPS
nframes = F / original_fps * target_fps

# 기본 최소 4장, 최대 768장 및 원본 프레임 수 제한
# 이후 2의 배수로 내림
nframes = ...

# 전체 비디오에 걸쳐 균일하게 선택
idx = torch.linspace(0, F - 1, nframes).round().long()
```

따라서 `1 FPS`는 정확히 `0초, 1초, 2초, ...` 프레임을 읽는다는 뜻보다는, **영상 길이 × 목표 FPS로 장수를 정하고 양 끝을 포함해 균일하게 고르는 방식**입니다. 장수는 영상 길이에 따라 달라지며, 항상 32장이나 64장으로 고정되지 않습니다. [장수 계산](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/qwen_vl_utils/vision_process.py:144), [프레임 인덱스 계산](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/qwen_vl_utils/vision_process.py:292)

해상도는 종횡비를 고려해 조정하며, 가로·세로를 `16 × 2 = 32`의 배수로 맞춥니다. `max_pixels=65536`은 **면적 예산**이므로 모든 프레임을 `256×256`으로 만드는 설정은 아닙니다. [리사이즈 코드](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/qwen_vl_utils/vision_process.py:448)

여기서 **샘플링 프레임 수와 LLM이 보는 시간축 길이는 다릅니다.** Qwen3-VL은 `temporal_patch_size=2`로 샘플링 프레임 두 장을 한 temporal group으로 처리합니다. 공간 방향은 `16×16` patch를 만들고 `2×2`로 merge합니다.

```text
샘플링한 프레임 수: N
리사이즈 크기: H × W

시간 그룹 수 T = N / 2
그룹당 시각 토큰 수 = (H / 32) × (W / 32)

전체 비디오 토큰 수 = T × (H / 32) × (W / 32)
```

예를 들어 120초 영상을 1 FPS로 120장 샘플링하고 `256×256`으로 처리했다면, 시간 그룹은 60개이고 비디오 토큰은 `60×8×8=3,840`개입니다. 이는 설명용 예시이며 실제 해상도는 비디오 종횡비에 따라 달라집니다. [Qwen 비디오 patch 처리](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/transformers/models/qwen3_vl/video_processing_qwen3_vl.py:234)

또한 processor는 각 시간 그룹 앞에 **초 단위 timestamp 텍스트**를 붙입니다. 두 프레임의 실제 샘플링 시각을 평균하고 소수점 한 자리로 표시합니다. HF extraction 입력을 도식화하면 다음과 같습니다.

```text
<|im_start|>user
<0.5 seconds><|vision_start|>[video tokens for group 0]<|vision_end|>
<2.5 seconds><|vision_start|>[video tokens for group 1]<|vision_end|>
...
Locate ... Event: {query}
<|im_end|>
<|im_start|>assistant
```

위 timestamp 값은 예시입니다. `[video tokens ...]` 부분은 실제로 `<|video_pad|>` 위치들이 시각 embedding으로 대체되는 부분입니다. [timestamp 삽입](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/transformers/models/qwen3_vl/processing_qwen3_vl.py:196), [timestamp 계산](/home/irteam/experiments/mtla_query_prefill_temporal_attention/.venv/lib/python3.10/site-packages/transformers/models/qwen3_vl/processing_qwen3_vl.py:314)

**Instruction prompt 원문은 데이터셋마다 다음과 같습니다.**

QVHighlights는 일치하는 모든 구간을 요구합니다.

```text
Locate every segment in the video where the following event happens. Respond with a list of [start, end] timestamps in seconds, one pair per segment. If the event happens multiple times, list all occurrences. Event: {query}
```

`{query}`에는 annotation의 `item["query"]`가 그대로 들어갑니다. [프롬프트 원문](/home/irteam/vtg_works/MTLA/mtla/data/qvhighlights.py:23)

Charades-STA는 하나의 구간을 요구합니다.

```text
Locate the segment where the following event happens. Respond with start and end timestamps in seconds. Event: {query}
```

`caption` 필드를 우선 사용하고, 없으면 `query`를 사용합니다. 문장 끝의 마침표는 `rstrip(".")`로 제거합니다. [프롬프트 원문](/home/irteam/vtg_works/MTLA/mtla/data/charades.py:26), [query 처리](/home/irteam/vtg_works/MTLA/mtla/data/charades.py:72)

두 프롬프트 모두 시간 단위는 **초**입니다. 비디오 길이로 정규화한 `0–1` 좌표나 프레임 번호를 출력하도록 요구하지 않습니다.

**답변은 시간 구간을 포함한 일반 텍스트로 생성합니다.** 기대 형태를 예로 들면 다음과 같습니다.

```text
# QVHighlights 답변 예시
[[12.0, 18.5], [42.0, 51.0]]

# Charades-STA 답변 예시
[8.2, 14.6]
```

이 예시는 실제 추론 결과가 아닙니다. 구현은 JSON schema로 디코딩을 강제하지 않고, 생성된 문자열을 정규식으로 파싱합니다. `[a, b]`뿐 아니라 `(a, b)`, `from a to b`, `between a and b`, `a - b` 등의 형태도 읽습니다. 시간 값은 `12.5` 같은 초 표현과 `1:30` 같은 `MM:SS` 표현을 지원합니다. [파싱 패턴](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:50)

파싱 후에는 다음 처리를 합니다.

- 시작이 끝보다 크면 두 값을 교환합니다.
- 길이가 0인 구간을 버립니다.
- 소수점 두 자리로 반올림한 `(start, end)`를 키로 중복을 제거합니다.
- 시작 시각 순으로 정렬합니다.
- QVHighlights는 모든 구간을 유지하고, Charades는 첫 구간만 유지합니다.

따라서 Charades에서 여러 구간이 생성되면 **시작 시각이 가장 빠른 구간**이 extraction 대상으로 남습니다. [파서](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:613), [단일 구간 선택](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:448)

**여러 후보 답변을 얻을 때는 프레임을 바꾸는 대신 생성 샘플링을 바꿉니다.** 기본 제공 설정에서 `--n 16`을 사용하면 다음 구성입니다.

| Rollout | 생성 방식 |
|---|---|
| 0 | greedy, `temperature=0` |
| 1–15 | stochastic, `temperature=0.7`, `top_p=0.95` |

입력 비디오와 query는 동일합니다. `--n`을 생략하면 기본 1회이므로, 이 비디오 데이터셋들의 기본 실행은 greedy rollout 하나입니다. [rollout 구성](/home/irteam/vtg_works/MTLA/generate.py:66)

**MTLA 신뢰도는 생성 답변을 다시 입력에 붙여 계산합니다.** 생성은 vLLM으로 수행하고, attention 추출은 Hugging Face 모델을 `attn_implementation="eager"`로 로드해 수행합니다.

```python
resp_ids = tokenizer(response, add_special_tokens=False)["input_ids"]
full_ids = concat(prompt_ids, resp_ids)

# full_ids로 한 번 forward하여 필요한 attention 행/열 추출
```

즉, 후보 생성 이후 **동일한 비디오와 프롬프트에 해당 답변을 teacher forcing**하여 attention을 읽습니다. [모델 로딩](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:101), [teacher forcing](/home/irteam/vtg_works/MTLA/mtla/mtla_attn.py:271)

이때 attention의 두 축은 다음과 같습니다.

| 축 | 선택 대상 |
|---|---|
| Query, attention을 보내는 쪽 | 생성 답변의 시작·끝 timestamp에서 숫자를 포함하는 토큰 |
| Key, attention을 받는 쪽 | 예측 시간 구간 안에 대응하는 비디오 시각 토큰 |

따라서 **입력 query 문장의 attention을 이용하는 방식은 아닙니다.** 예를 들어 답변이 `[12.0, 18.5]`라면 그 시간 숫자에 해당하는 response token들을 찾습니다. 순수 괄호·쉼표 토큰은 제외됩니다. 위치는 `prompt_len + response_token_index`를 사용하며, 이전 위치로 `-1` shift하지 않습니다. [답변 토큰 선택](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:537), [절대 위치 계산](/home/irteam/vtg_works/MTLA/mtla/mtla_attn.py:220)

예측 구간 `[s, e]`를 비디오 토큰으로 변환하는 코드는 다음과 같습니다.

```python
# D: 비디오 길이(초), T: temporal group 수
fs = max(0, floor(s * T / D))
fe = min(T, ceil(e * T / D))

# fs 이상 fe 미만 그룹의 모든 공간 토큰
region_tokens = [
    f * HW + k
    for f in range(fs, fe)
    for k in range(HW)
]
```

여기에는 구현상 구분할 점이 있습니다. **입력 timestamp 텍스트는 실제 샘플 프레임 시각에서 계산하지만, attention 영역 mask는 `D/T` 간격의 균일 시간축으로 근사합니다.** 실제 timestamp 배열을 직접 비교해 mask를 만들지는 않습니다. [시간 구간 mask](/home/irteam/vtg_works/MTLA/mtla/models/qwen3vl.py:582)

일반적인 MTLA 계산은 아래와 같습니다.

```python
# attn: [layers, heads, selected_response_tokens, video_tokens]
local = attn[..., region_tokens].sum(-1)  # 구간 내부 토큰 attention 합
local = local.mean(-1)                  # response token들 평균
score = local[8:22].mean()              # layer 8~21 및 모든 head 평균
```

구간 내부 토큰 수로 나누는 평균이 아니라 **구간 내부 attention의 합**을 사용합니다. layer 번호는 코드상 0-based 인덱스입니다. [attention 집계](/home/irteam/vtg_works/MTLA/mtla/mtla_attn.py:64), [layer/head 집계](/home/irteam/vtg_works/MTLA/mtla/mtla_attn.py:97)

다만 **현재 비디오 기본 평가는 multi-token 평균 대신 `first_local`을 사용합니다.** 이 부분은 논문의 일반적인 MTLA 설명과 실제 실행 설정을 구분해서 봐야 합니다.

```python
# QVHighlightsDataset, CharadesDataset 양쪽의 기본값
slot = "first"
attn_scope = "local"

# evaluate.py
signal = f"{slot}_{attn_scope}"  # "first_local"
```

즉, 기본 비디오 점수는 **해당 구간의 첫 번째 숫자 토큰 한 개 → 예측 구간 내부 비디오 토큰들의 attention 합 → layer/head 평균**입니다. 추출 단계는 `all_local`, `digits_local`, `first_local`을 모두 계산하지만, 평가 단계가 `first_local`을 선택합니다. [QVHighlights 기본값](/home/irteam/vtg_works/MTLA/mtla/data/qvhighlights.py:43), [Charades 기본값](/home/irteam/vtg_works/MTLA/mtla/data/charades.py:45), [평가 신호 선택](/home/irteam/vtg_works/MTLA/evaluate.py:71)

**최종 답변은 attention 점수가 붙은 후보들을 데이터셋별로 선택해 만듭니다.**

| 처리 | QVHighlights | Charades-STA |
|---|---|---|
| 후보 풀 | 모든 rollout의 모든 구간 | 각 rollout에서 남긴 단일 구간 |
| 중복 처리 | temporal IoU ≥ 0.5로 NMS | 공통 NMS 경로 후 top-1 |
| 기본 점수 결합 | cluster 내 최대 점수 `max` | 동일 |
| 최종 반환/평가 대상 | 점수순 최대 10개 구간 | 가장 높은 점수의 1개 구간 |
| 평가 지표 | moment retrieval mAP, R@1 | R@1@{0.3, 0.5, 0.7}, mIoU |

NMS는 최고 점수 후보의 좌표를 유지합니다. 여러 후보의 시작·끝 시간을 평균해 새 구간을 만드는 처리는 없습니다. Charades의 기본 `max + top-1`은 결국 전체 후보 중 최고 attention 점수 구간을 선택하는 것과 같습니다. [NMS 구현](/home/irteam/vtg_works/MTLA/mtla/voting.py:68), [top-1 처리](/home/irteam/vtg_works/MTLA/evaluate.py:298)

QVHighlights evaluator에 전달하는 형식은 다음과 같습니다.

```python
{

    "pred_relevant_windows": [
```
