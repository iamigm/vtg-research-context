## 2026-09-30T04:56:46.859Z — Codex final report

**같은 시간에 속한 모든 공간 패치 토큰의 attention을 합산했습니다.** 그 후 query 토큰·head·layer에 대해 평균했습니다.

attention을 \(A_{\ell,h,q,t,p}\)라고 하면, 시간 \(t\)의 점수는 다음과 같습니다.

\[
s_t=\frac{1}{14\cdot32\cdot |Q|}
\sum_{\ell=8}^{21}\sum_{h=1}^{32}\sum_{q\in Q}
\underbrace{\sum_{p\in P_t}A_{\ell,h,q,t,p}}_{\text{해당 시간의 공간 패치 합산}}
\]

공간 패치를 합산하는 이유는 **그 시간에 할당된 전체 probability mass**를 구하기 위해서입니다. 실제 [집계 코드](/home/irteam/experiments/mtla_query_prefill_temporal_attention_100/run_attention.py:186)는 다음과 같습니다.

```python
# video: [heads, query_tokens, 전체 video_tokens]
temporal = video.reshape(heads, query_tokens, T, spatial_tokens).sum(-1)
```

정확히 짚으면, 앞서 “프레임”이라고 표현한 단위는 **원본 프레임 한 장이 아니라 temporal bin**입니다. 이 모델 설정은 `temporal_patch_size=2`여서 샘플링된 프레임 2장이 하나의 temporal bin으로 묶입니다. 공간 방향도 `2×2` merge를 거친 **LLM 입력 visual token**을 기준으로 합니다.

예를 들어 첫 Charades 샘플은 grid가 `[29, 30, 16]`이므로, 시간 bin마다 `30×16÷4 = 120개` visual token의 attention을 합산했습니다.

GT mass는 이렇게 얻은 \(s_t\)를 \(p_t=s_t/\sum_t s_t\)로 정규화하고, 각 bin이 GT와 겹치는 비율만큼 더한 값입니다. 따라서 개별 원본 프레임 내부까지 구분하는 해상도는 아닙니다.

## 2026-09-30T05:13:26.724Z — Codex final report

:codex-annotation{index="1"} **`[29, 30, 16]`은 `[시간 bin 개수, 세로 패치 개수, 가로 패치 개수]`입니다.** 여기서 `30`은 FPS가 아니고, `29`도 초가 아닙니다. 제가 설명을 너무 압축했습니다.

| 값 | 의미 |
|---|---|
| **29** | 시간 방향으로 29개 bin |
| **30** | 이미지의 세로 방향으로 패치 30개 |
| **16** | 이미지의 가로 방향으로 패치 16개 |

이 Charades 실험에서는 영상을 **약 2 FPS로 샘플링**하고, 샘플링한 프레임 **2장씩을 하나의 시간 bin**으로 묶습니다. 따라서 29개 bin은 샘플링 프레임 58장에 대응합니다. 대략 1초에 bin 하나인 셈이지만, 정확한 시간은 실제 프레임 timestamp로 정합니다.

각 bin의 공간 격자는 `30×16 = 480개` 패치입니다. 모델이 인접한 **2×2 패치를 토큰 하나로 합치므로**, LLM에 들어가는 공간 토큰은 다음과 같습니다.

\[
(30/2)\times(16/2)=15\times8=\boxed{120개}
\]

즉, **“한 시간 bin에 속한 120개 공간 토큰으로 향하는 attention을 모두 더했다”**는 뜻입니다.

## 2026-09-30T05:14:36.501Z — Codex final report

**LLM에 전달하는 영상 토큰 수를 줄이는 구조적 압축입니다.** “480개를 못 받아서 이번 입력에서만 줄였다”는 뜻은 아니고, 이 모델은 **항상 공간 패치를 2×2씩 병합하도록 학습돼 있습니다.**

앞의 예시는 다음 순서입니다.

```text
시간 bin 하나의 공간 패치 480개
          ↓
Vision encoder가 480개 패치의 특징을 처리
          ↓
인접한 2×2 특징을 연결하고, 학습된 MLP로 변환
          ↓
LLM에 visual token 120개 전달
```

따라서 **해상도와 관련은 있지만, 입력 이미지를 단순히 축소하는 것과는 다릅니다.** 세밀한 패치 특징을 먼저 처리한 뒤 공간적으로 묶어서 전달합니다. 단순 평균도 아닙니다.

이렇게 하면 LLM이 처리할 영상 토큰 수가 ¼로 줄어 연산·메모리·문맥 길이 부담이 감소합니다. 이 예시에서는 영상 전체가 `29×480 = 13,920개`에서 `29×120 = 3,480개`로 줄어듭니다.

우리 실험이 측정한 것은 **LLM의 query → 병합된 120개 visual token attention**입니다. 따라서 그 안의 원래 480개 패치 각각에 대한 attention까지 구분할 수는 없습니다.
