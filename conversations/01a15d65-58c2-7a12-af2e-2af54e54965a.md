## 2026-10-21T07:54:31.282Z — User

Instruct와 Thinking의 차이는 뭐야? 그리고 메모리의 35%로 제한한 이유는?


## 2026-10-21T07:55:04.249Z — Codex final report

**Instruct는 바로 답변하는 용도, Thinking은 추론에 더 많은 토큰을 쓰는 용도**입니다. 지금 사용하는 Qwen3-VL 기준으로 보면:

| 구분 | Instruct | Thinking |
|---|---|---|
| 응답 방식 | 지시에 따라 바로 답변 | 추론 내용을 생성한 뒤 최종 답변 |
| 적합한 작업 | 일반 채팅, 요약, OCR, 이미지 설명 | 수학, 논리, 복잡한 도표·이미지 추론 |
| 응답 시간 | 대체로 짧음 | 추론 길이에 따라 길어짐 |
| 가중치 용량 | 같은 크기 모델끼리 동일 | 동일 |
| 실행 메모리 | 입력·출력 길이에 따라 달라짐 | 긴 추론으로 KV 캐시 사용량이 늘 수 있음 |

Qwen3-VL에서는 **서로 다른 가중치**라서 모델을 교체해야 합니다. Thinking이 모든 작업에서 더 좋은 것은 아니며, 간단한 작업은 Instruct가 효율적입니다. [공식 Instruct 설명](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct), [Thinking 설명](https://huggingface.co/Qwen/Qwen3-VL-8B-Thinking)

**35%는 다른 실험에 GPU 메모리를 남기려는 앱의 기본 설정입니다.** 모델이나 H200의 필수 제한은 아닙니다. 이 이유는 [프로젝트 README](/home1/irteam/qwen-chat/README.md:94)에 명시되어 있습니다.

- 전체 GPU 메모리 중 약 **49.1 GiB**를 이 vLLM 실행기의 예산으로 잡습니다.
- **GPU 연산 성능을 35%로 제한한다는 뜻은 아닙니다.**
- 설치된 vLLM의 기본값은 **90%**이고, 이 앱에서 35%로 낮춘 것입니다. [vLLM 설정 문서](https://docs.vllm.ai/en/v0.11.2/api/vllm/config/cache/#vllm.config.cache.CacheConfig.gpu_memory_utilization)

따라서 **채팅할 때 H200을 단독 사용한다면 35%를 고집할 이유는 없습니다.** 특히 32B는 가중치만 약 62~64 GiB라서 비율을 높여야 합니다. 다만 비율을 높이는 것 자체가 답변 품질을 높이지는 않고, 더 큰 모델·긴 문맥을 실행할 여유를 줍니다.

## 2026-10-21T07:57:20.310Z — User

VTG에서는 instruct가 쓰이는 이유는?


## 2026-10-21T07:58:07.330Z — Codex final report

**VTG는 문장에 해당하는 영상 구간을 찾아 시작·종료 시각을 출력하는 작업이라, Instruct가 효율적인 기본 모델이 됩니다.** 다만 Thinking도 사용할 수 있고, 어느 쪽이 정확한지는 비교 실험이 필요합니다.

Instruct를 쓰는 실용적인 이유는 다음과 같습니다.

- **필요한 출력이 짧습니다.** 예를 들어 “사람이 컵을 내려놓는 구간”에 대해 `[12.3, 15.8]`을 반환하면 됩니다. 긴 추론을 생성하지 않으면 생성 시간과 토큰 비용을 줄일 수 있습니다.
- **시각·시간 이해 능력이 이미 있습니다.** Instruct도 영상 내용을 해석하고 추론합니다. Qwen3-VL에는 프레임과 타임스탬프를 연결하는 학습이 포함되어 있어, 시간 구간을 직접 예측할 기반이 있습니다. [공식 모델 설명](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct)
- **긴 추론이 시간 경계의 정확도를 보장하지는 않습니다.** 프레임 샘플링에서 놓친 짧은 동작이나 모호한 시작·종료 경계는 설명을 길게 생성한다고 반드시 해결되지는 않습니다. 이는 작업 특성에 따른 판단이며, Instruct의 성능 우위를 입증한 결과는 아닙니다.

**현재 서버의 실험은 Instruct를 기준선으로 사용하고 있습니다.** Qwen3-VL-8B-Instruct에 `do_sample=false`, `max_new_tokens=512`를 적용한 설정이 확인됩니다. 다만 확인한 기록에는 **Thinking과 비교해서 Instruct가 더 좋아 선택했다는 근거는 없습니다.** [실험 설정](/home/irteam/experiments/zero-shot/predictions/qwen3/run_config.json)

Thinking은 “컵을 내려놓은 **뒤**, 다른 사람이 들어오기 **전**에 문을 여는 구간”처럼 사건 순서·관계 해석이 복잡한 질의에서 도움이 될 가능성이 있습니다. 검증하려면 같은 영상 입력으로 **mIoU·R@IoU, 출력 파싱 성공률, 생성 시간**을 함께 비교해야 합니다. 이때 Thinking에 기존 512토큰 제한을 그대로 적용하면 최종 시간 구간을 출력하기 전에 잘릴 수 있으므로, 추론 토큰 예산도 고려해야 합니다.
