# Compute cost · pilot300

고정 cohort 300 query의 샘플별 추가 연산 분포다. 후보 탐색은 300/300 완료. 후속처리도 300/300 완료하여 포함한다.

이 문서는 같은 분석의 appendix이며 별도 실험이 아니다. pilot300은 pilot900의 정확한 prefix다. 두 범위를 독립 표본처럼 합산하지 않는다. 모든 값은 저장된 실측을 집계하며 새로운 추론이나 시간 추정을 하지 않는다.

## 비용을 읽는 방법

- 한 행의 n은 조건 반복 수가 아닌 query 수다. 각 query를 같은 가중치로 평균한다.
- 평균 μ=Σx/n, 중앙값=정렬한 가운데 값(짝수이면 두 값 평균), 분산=Σ(x−μ)²/n인 population variance, 표준편차=√분산이다. 분산 단위는 표에 적힌 단위의 제곱이다.
- 최소·최대는 실제 관측값이다. P90·P95는 정렬 위치 (n−1)p의 선형 보간 quantile이다. 비용 지표는 대체로 작을수록 좋으며, 분산은 샘플별 비용의 불균일함을 뜻한다.
- 최초 값은 cohort 첫 query의 값이며 실행 startup의 독립 측정이 아니다. 최소·최대 query와 함께 문서 끝에 제시한다.
- decoder inputs는 실제 모델에 넣은 position 수로 prefix replay를 포함한다. Forward 호출 수·token 수·CUDA event 시간·wall time은 서로 다른 지표이며 FLOPs로 환산하지 않는다.
- 512·1024·2048은 한 탐색의 누적 checkpoint다. checkpoint 세 개를 합산하지 않는다. 서로 다른 방법은 별도로 실행했다.
- search는 greedy 답변을 얻은 뒤 후보를 확장하는 추가 비용이다. shared video/query prefill은 search에 포함하지 않고 한 번만 센다. 같은 GPU의 동시 작업, CPU 준비, KV 관리 때문에 token 비율과 wall 비율은 다를 수 있다.

## 후속처리 조건별 귀속 원칙

아래 verifier는 그 조건에서 제안한 고유 crop만 센다. 같은 crop은 한 query·조건 안에서 한 번 센다. 원래 후보에 없고 greedy 참조용으로만 추가한 crop은 제외한다. 입력 token은 해당 crop의 실측이고 시간은 batch 시간을 token 비율로 나눈 귀속값이다. 독립 실행 latency가 아니다. 최초 검증의 재실행·버린 batch는 조건별로 임의 배분하지 않고 다음 공유 실행 표에 포함한다.

final generation은 해당 prompt의 실제 측정값을 각 조건에 참조한다. 같은 prompt를 공유한 조건을 더하면 중복 계산이므로 조건 행끼리 합산하지 않는다. reviewed search+verify+final model wall은 후보 탐색+귀속 verifier wall+full-video final prefill 한 번+reviewed generation wall이다. 기존 greedy/prefill·CPU crop 준비·semantic 진단·검증 재실행은 제외하며, 이 합은 측정 단계의 회계 합계다. end-to-end 단독 latency로 해석하지 않는다.

## 공유 실행 총비용의 범위

다음 표는 세 방법×세 예산과 두 final variant의 후보 합집합을 실제 공유 실행한 query별 비용이다. 개별 방법·예산 비용이 아니며 조건별 표에 더하지 않는다. Instruct visual mean과 last-token pooling은 같은 forward에서 얻으므로 Instruct 비용은 한 번만 센다. Embedding은 별도 모델 비용이다. Semantic 계산은 진단 전용이며 final answer를 선택하는 데 필요하지 않다. Batches+validation은 최초 검증과 기록된 버린 batch까지 포함한다.
