## 후보 품질과 zero-shot 대비 차이

IoU=예측·GT 교집합 길이÷합집합 길이,mIoU=query별 IoU 평균,R@τ=IoU≥τ 비율이다. 높을수록 좋다. 괄호 안Δpp=100×(결과−같은 query의zero-shot greedy). Greedy는 동일 입력의 새 native generation이며 clipping·평가 정책도 같다. GT는 탐색 후 평가에만 사용한다.

## Viewer용 token distribution 보충

초기 원자료에 실제 numeric fork의 분포만 남아 있어, 나머지 계산 위치의 native top30을 동일 입력 hash·동일 token prefix로 보충한다. 이후 query는 탐색 시 모든 계산 위치의 분포와 정책 이유를 직접 기록해 별도 재계산을 줄인다. 탐색에서 직접 저장한 분포와 기존 deterministic trace를 먼저 재사용하고 누락 prefix만 single-token KV 실행으로 재계산한다. 새 후보를 생성하거나 기존 탐색의 node·확률·예산 배분·정답을 바꾸지 않는다. 소수 자릿수의 token distribution 표시는 fractional branching 또는 branch entropy 측정이 아니다.

현재 범위에서 보충을 마친 query 34 / 300개. 아직 분포가 없는 위치는 viewer에서 보충 대기로 표시한다. 보충 작업은 누적 원자료에만 저장하며 pilot별로 복제하지 않는다.

| 항목 | 값 |
|---|---:|
| 탐색에서 직접 저장한 위치 | 557 |
| 기존 reference 재사용 위치 | 2140 |
| 다른 방법에서 관측한 동일 prefix 재사용 위치 | 0 |
| 새로 재계산한 고유 prefix | 7378 |
| 보충 prefill 입력 합 | 101433 |
| 보충 decoder inputs 합 (replay 포함) | 8549 |
| 보충 작업 wall 합 s | 393.352 |
| 보충 CUDA decode 합 s | 345.120 |
| 저장된 경로 확률과 최대 절대 차이 | 0.00000000 |

보충 inputs와 wall은 위 search 예산·비용에 합산하지 않는 관측용 추가 비용이다. 고유 prefix 수는 같은 입력의 정확히 같은 token ID prefix를 한 번 센 값이다. 확률 차이는 각 prefix에서 원래 추적한 자식 token의 native 확률과 재계산 확률의 절대 차이이며 낮을수록 재현이 정확하다. Wall 합은 query별 실측 합이며 작업 전체 경과 시간이나 전용 GPU 성능을 뜻하지 않는다.

공통 완료 query 중 보충 프로세스와 실행 시간대가 겹친 query는 8 / 238개다. Search wall·CUDA event 시간은 실제 실행값이므로 같은 GPU에서 보충 작업이 실행된 동안의 자원 경합을 포함할 수 있다. 해당 wall 수치를 보충 작업이 없는 전용 GPU의 search 비용으로 해석하지 않는다. 실행 시간대는 metadata/distribution_execution.json, 보충 작업별 비용은 token_distributions와 logs/distribution_capture.log에 남긴다.


## 해석 범위

현재 얻은 interval entropy·variance는 관측 유효 분포에 조건부다. 종료 시 남은 질량·context limit·정책 제외 질량을 함께 확인한다. Candidate oracle 향상이 최대 native-mass 답의 성능 향상을 의미하지 않는다. Novelty는 시간적 차이이며 사건 semantic이나 정답 여부를 판별하지 않는다.
