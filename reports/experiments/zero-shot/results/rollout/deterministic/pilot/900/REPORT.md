# deterministic rollout: 고정 중첩 pilot900 성능과 계산량

고정 중첩 pilot900, 총900질문. 데이터셋별 질문 수: {'charades-timelens': 300, 'activitynet-timelens': 300, 'qvhighlights-timelens': 300}. 원래 프롬프트·2 FPS·공간 입력 유지. 시간 토큰의 대안을 중복 없이 선택한 뒤 원래 prefix 조건에서 EOS까지 greedy 완성했다. 숫자/소수점/콜론 위치를 기록하고 MM:SS/HH:MM:SS는 평가에서만 초로 환산했다.

주 지표는 연속 시간 IoU=교집합 길이/합집합 길이, mIoU=900질문 평균, R@τ=IoU≥τ 질문 비율이다. 높을수록 좋다. clipping·반올림은 하지 않는다. 파싱 실패·역전 구간·EOS 미도달은0점이며 영상 길이 초과는 별도 표시한다. MAE는 유효 응답에 조건부인 초 단위 절대오차로 낮을수록 좋다.

max_probability는 관측한 완성 경로 중 raw 전체 응답 확률이 가장 높은 답을 고른다. medoid는 후보 간 IoU 합의가 높은 답, probability_weighted_medoid는 관측 path probability로 가중한 합의가 높은 답이다. 이 세 선택기는 GT를 사용하지 않는다. oracle은 GT로 고른 후보 집합 상한이며 실제 성능과 구분한다. 결정적 후보 열거 빈도를 샘플링 빈도나 모델의 사건 확률로 해석하지 않는다.

## 오답 복구·정답 훼손·후보 선택 실패

각 기준 τ에서 G는 greedy IoU≥τ, S는 최종 선택 IoU≥τ, O는 후보 중 하나라도 IoU≥τ인 질문이다. 아래 세 선택기는 GT를 쓰지 않는다. 성공 판정에만 GT를 사용한다. 각 행은 전체 질문을 대상으로 하며 분모가0이면 —로 표시한다.

- 오답 복구율 = |¬G∧S| / |¬G|. 기존 오답을 고친 비율로 높을수록 좋다.
- 정답 훼손율 = |G∧¬S| / |G|. 기존 정답을 잃은 비율로 낮을수록 좋다.
- 선택 실패율 = |O∧¬S| / |O|. 후보 안에 정답이 있는데도 선택에 실패한 비율로 낮을수록 좋다.
- 새 정답 채택률 = |¬G∧S| / |¬G∧O|. greedy는 틀렸고 새 정답 후보가 생긴 경우 그 답을 고른 비율로 높을수록 좋다. 미채택률은1−채택률이다.
- 순증 성공률(pp) = 100×(복구 수−훼손 수)/N. 복구와 훼손을 상쇄한 전체 성능 변화다.

## 분기 위치별 개선과 시작→종료 변화

여기서 분기는 생성 도중 한 토큰을 다른 토큰으로 바꾸고 나머지를 끝까지 생성하는 것이다. 부모 후보는 바꾸기 전 완성 답, 자식 후보는 바꾼 뒤 완성 답이다. 부모는 최초 greedy일 수도 있고 탐색 중 생성한 다른 후보일 수도 있다.

표의 내부 코드는 분기 전 부모 답에서 그 토큰이 차지한 위치를 적은 이름이다. `start`는 시작 시각, `end`는 종료 시각이다. `seconds`는 초 필드, `minutes`는 분 필드, `hours`는 시 필드다. `10^2`, `10^1`, `10^0`, `10^-1`은 각각 백·십·일·소수 첫째 자리다. 예를 들어 `135.7`에서 `3`은 십의 자리이고 `7`은 소수 첫째 자리다.

`decimal_separator`는 소수점 아래 숫자가 아니라 소수점 기호 `.` 자체다. 따라서 `end.seconds.decimal_separator`는 종료 시각의 초 필드에서 소수점 자체를 바꾼 분기를 뜻한다. `clock_separator`는 예외적인 시:분:초 표기의 구분 콜론 `:`이다. 예를 들어 `2:11`은 분 필드2와 초 필드11로 나눈다.

원자료의 `source_roles`는 분기 전 위치 이름, `target_roles`는 변경 후 완성 답에서 같은 토큰의 위치 이름이다. 소수점 대신 숫자를 넣으면 정수 부분이 길어질 수 있으므로 분기 전후 자릿수 역할이 같다는 뜻은 아니다. 표는 한국어 이름과 내부 코드를 함께 표시한다.

개선/악화 비율과 부모 대비 평균 ΔIoU는 자식 IoU−부모 IoU 기준이다. 최초 greedy 대비 평균 ΔIoU는 자식 IoU−최초 greedy IoU로 별도 표시한다. 개선/악화는 차이가 ±1e−9를 넘는 경우이고 실패 응답의 IoU는0이다. 여러 후보를 최종 선택하기 전의 후보별 진단이므로 실제 선택 성능과 구분한다.

한 질문에서 여러 분기가 나오며 각 분기는 서로 독립 표본이 아니다. 여러 자릿수를 담는 토큰은 각 역할 행에 중복 집계될 수 있다. 아래 비율은 이 탐색 정책이 생성한 분기들에 조건부인 빈도이며, 자릿수의 일반적인 인과 효과나 모델 전체 분포의 확률로 해석하지 않는다.

### 종료 시각 소수점 분기의 해석

종료 시각의 소수점 위치를 바꾼 분기는 84질문에서 243개였다. 그중 243개는 변경 후 해당 토큰이 숫자 자릿수가 됐다. 소수점을 숫자로 바꾸면 예를 들어 `1.3`이 `107.3`처럼 길어질 수 있다. 이는 소수 첫째 자리를 미세 조정하는 것과 다르며, 정수 부분을 너무 일찍 끝낸 후보를 고치는 분기일 수 있다.

## 영상 검토가 필요한 지표: 아직 측정하지 않음

- 다른 사건 후보 발견율: greedy가 잘못된 사건 occurrence를 가리킨 질문 중 정답 occurrence 후보가 생긴 비율. 영상 검토로 사건 occurrence 라벨을 정해야 한다.
- 같은 사건 내 경계 개선율: 부모·자식이 같은 occurrence를 가리키는 분기 중 시작/종료 MAE가 감소한 비율과 감소량. 위 전체 경계 MAE로 대체하지 않는다.
- 사건 이탈률: 올바른 occurrence였던 답이 분기/선택 후 다른 occurrence로 바뀐 비율. 단순한 시간 거리나 낮은 두 후보 IoU만으로 판정하지 않는다.
현재 기록에는 occurrence 라벨이 없어 위 세 지표의 수치는 미측정이다. 조건부 종료 변화는 측정했지만 다른 사건 발견 또는 같은 사건 refinement 성공으로 단정하지 않는다.

## 샘플별 분기 확인

[Rollout 분석 HTML](viewer.html) · [종료 소수점 84개 샘플](viewer.html#preset=dot) · [전체 사례 목록](END_DECIMAL_CASES.md)

샘플 탐색은 모든 샘플·ID순이 기본이며, 사례 유형 선택과 IoU·ΔIoU·분기 토큰 순번·대체 토큰 확률의 수치 범위를 함께 적용한다. 분기 경로는 dropdown 없이 계층형 지도에서 선택한다. 들여쓰기는 부모 관계를 나타내며, 각 경로의 실제 응답 문장 안에서 바뀐 토큰을 강조해 분기 위치를 표시한다. 선택한 후보의 이력과 공통 prefix를 보여주고, 부모 응답과 분기 응답의 완성 문장을 나란히 비교한다. 모바일에서는 두 문장을 위아래로 연결한다. 각 문장에서 공통 prefix, 분기 토큰, 이후 생성 부분을 구분한다. 후보 선택은 비교할 완성 후보와 직접 부모를 바꾸며, 디코딩 토큰 선택은 그 응답 쌍을 유지하고 확률 분포를 볼 위치만 바꾼다. greedy 응답과 직접 부모가 다르면 따로 표시한다.

Token 경로·분포 탐색은 토큰 선택과 조건부 token distribution를 하나의 화면으로 통합한다. 부모·분기 응답의 문장 속 토큰을 누르면 그 토큰을 선택하기 직전의 prefix를 조건으로 한 분포표 하나가 갱신된다. 다음 위치의 별도 분포표나 중복 토큰 이력은 표시하지 않는다. 문장 안의 같은 토큰 셀에서 조건부 확률과 누적곱 표시를 켤 수 있으며, 최종 path probability는 EOS까지 포함한다. 토큰 확률 pᵢ = P(tokenᵢ | prefix), 누적곱은 응답 시작부터 해당 토큰까지의 ∏pᵢ이며, 확률이 클수록 모델이 부여한 가능성이 높다. 정답일 확률로 해석하지 않는다.

분포는 top-k 또는 top-p로 선택하며, 기본 k는5다. 직접 입력한 k와 확률 상세 표시 여부는 토큰 위치와 후보를 바꿔도 유지한다. 상위30개로 기준을 만족하지 못하면 전체 어휘 FP32 원자료에서 정확히 계산한다. 기준 밖 경로 토큰은 별도로 표시하고 재정규화하지 않는다. 검색은 전체 어휘에서 수행한다. 긴 집합은80개씩 추가 표시한다. 분포표의 색이 있는 토큰을 누르면 그 토큰을 선택한 저장 경로로 이동하고, 다른 저장 경로를 추가해 비교할 수 있다. 부모·분기 응답은 위치 탐색 중에도 유지한다. 이전 토큰·분기 위치 복귀와 경로별 다음 토큰 이동을 제공한다.

응답 문장과 예측 요약은 하나의 비교 영역에 통합한다. 정답 구간은 공통 기준으로 한 줄에 표시한다. 부모·분기 응답은 동일한 형식의 카드에서 완성 문장, 강조한 분기 토큰, 예측 구간, IoU, 생성 방식과 구간 재생을 함께 제공한다. 분기 위치는 문장 안에서만 강조하고, 토큰 역할 분류를 반복하는 별도 행은 두지 않는다. 재생 버튼은 예측 구간 옆에 작게 배치한다. 부모 대비 ΔIoU는 비교 영역의 공통 요약으로 표시한다. greedy 응답만 선택하면 응답 카드도 하나만 표시한다.

영상 재생·응답 원문·토큰 비교는 하나의 검토 영역이다. 원래 응답·성능 수치는 유지한다. 원자료는900개 실행의 token_traces와 web/samples를 공유하며 pilot마다 복제하지 않는다.

## 토큰 분포와 generation step 확률의 곱

기존900개 rollout 실험에 토큰 분포 측정을 통합했다. 별도 분포 실험이 아니라 동일 코호트의 기존 HTML에서 확인한다. 총900개 질문, 199,189개 고유 prefix의 전체 어휘 FP32 확률을 기록했다. 참조하는 압축 원자료 크기는 52.37GiB다. 원래 응답·평가 수치는 유지했다.

조건부 토큰 확률은 P(다음 토큰 | 영상·질문·현재 prefix)이다. 누적 경로 확률은 각 generation step의 조건부 확률을 곱한 값이고, 전체 응답 확률은 EOS까지 포함한다. 부모에서 선택한 토큰을 서로 다른 색으로 표시하고, 각 토큰을 붙인 뒤의 자식 분포는 같은 색으로 비교한다. 표시한 상위 토큰 안에서 재정규화하지 않으며 나머지 확률도 표시한다.

원래 입력 tensor hash, greedy suffix, 강제 토큰 확률과 전체 응답 확률 곱을 검증했다. [기존 샘플별 HTML에서 보기](viewer.html#panel=distributions). 원자료는 전체900개 실행의 token_traces를 공유하며 pilot별로 복제하지 않는다.
