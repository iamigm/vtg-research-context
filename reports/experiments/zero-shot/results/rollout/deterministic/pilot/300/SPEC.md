# 고정 pilot300 deterministic rollout: 성능과 비용

고정 pilot300 전체300질문(데이터셋별100개), 객체·순서를 변경하지 않는다. 기존30개 진단은 포함되므로 독립 test라고 부르지 않는다. 모델은 로컬 Qwen3-VL-8B-Instruct이며 기존 TimeLens 프롬프트·video_query·2 FPS·목표100,352픽셀 고정 H/W 입력을 그대로 재사용한다. 프롬프트는 여전히 초 단위 응답 형식을 요구한다.

## 후보 생성

최초 greedy 응답을 포함해 질문당 최대32개의 서로 다른 완성 토큰 경로를 만든다. 후보1/4/8/16/32 시점의 결과와 실제 계산량을 모두 보존한다. 무작위 sampling은 수행하지 않는다.

완성 응답의 시작·종료 숫자 위치에서 원래 토큰 prefix를 고정하고 대안 토큰 하나를 강제한 뒤, 이후는 전체 어휘의 원래 logits로 EOS까지 greedy 완성한다. 강제 토큰 이후의 시작·종료 값이나 표기를 문법으로 제한하지 않는다. 따라서 시작의 대안은 원래 모델에서 종료의 조건부 분포를 바꾼다.

각 위치의 숫자/소수점/콜론 토큰을 raw 확률순으로 최대4개(선택된 원래 토큰 포함), 최소 raw 확률0.0001, 누적 raw 확률목표0.95까지 고려한다. 이 제한 때문에 누락한 확률도 기록하며 재정규화하지 않는다. 후보 prefix의 원래 전체 경로확률을 우선순위 상한으로 사용한다. 관측 후보가 전역 상위32개라고 보장하지 않는다.

한 후보에서 새 분기를 만들 때 마지막 강제 위치 이후만 분기해 경로가 겹치지 않게 한다. 같은 prefix·완성 토큰 경로를 중복 생성하지 않는다. 동일 수치 구간을 다른 토큰 경로로 생성하면 별도 기록하고 고유 수치 구간 수도 보고한다. 탐색 가능한 대안이 먼저 소진되면 실제 후보 수를 표시하고 해당 질문을 평가 분모에서 제외하지 않는다.

자릿수는 시작/종료, 초 단위 백·십·일·소수 자리로 기록한다. 분:초·시:분:초 예외에는 각 필드와 자릿수를 별도 기록하고 평가할 때만 초로 환산한다. 표기를 강제 변환하거나 새 프롬프트를 쓰지 않는다. 원래 응답에서의 자리(source roles)와 강제 후 완성 응답에서의 자리(target_roles)를 둘 다 기록해99→100 같은 자릿수 변화도 구분한다.

## 성능과 비용

- greedy, 관측 후보 중 전체 응답 경로확률1위, 후보 간 temporal IoU 합의 medoid, 관측 경로확률 가중 medoid를 비교한다. 세 선택기는 GT를 사용하지 않는다. 확률가중 합의를 모델의 보정된 사건 확률로 해석하지 않는다.
- GT를 보고 최선 후보를 고르는 oracle은 후보 집합의 가능성을 보는 상한으로 분리한다.
- mIoU와 IoU≥.3/.5/.7 성공률, greedy 대비 변화(pp), 영상 단위 paired bootstrap95% CI를 보고한다. 영상 길이·GT/영상 길이 비율·두 축 교차표를 네 지표별로 생성한다.
- IoU는 원래 연속 시간 구간의 교집합 길이/합집합 길이이며 높을수록 좋다. 반올림·clipping은 없다. 파싱 실패·시작≥종료·EOS 미도달은0점이다. 영상 길이 초과는 별도 표시한다. 모든 방법의 평가 기준을 동일하게 적용한다.
- 시작/종료 MAE(초)는 유효 응답에 조건부인 절대오차로 낮을수록 좋다. 자릿수 분기별 시작·종료 변화도 기록한다. 영상 검토 전에는 다른 사건 발견 또는 동일 사건 refinement 성공으로 단정하지 않는다.
- 추가 계산량은 최초 greedy 대비 실제 decoder 토큰 수·forward 호출·경과시간으로 측정한다. KV rollback 재계산을 포함하고 prefill 시간은 별도 보존한다. 선택은 CPU에서 수행하며 추가 모델 검증 호출은 없다.

## 실행과 검증

GPU 여유60GiB 이상일 때 실행한다. 기존 다른 작업은 중단하지 않는다. 한 모델 프로세스, Torch2 threads로 운영하며 고정 입력 캐시를 재사용한다. CPU quota와 메모리 제한을 provenance에 기록한다.

데이터셋별 첫 질문에서 branch rollback과 새 캐시의 동일 단일토큰 replay 분포를 비교한다. 기존30개와 겹치는 질문은 입력 hash와 greedy 토큰이 동일한지도 검증한다. MM:SS/HH:MM:SS 환산, 자릿수 역할, 중복 없는 분기·종료 조건부 변화의 CPU 합성 검증을 먼저 수행한다.

추론은 detached 프로세스로 실행하고20초 간격 heartbeat와 질문별 진행/ETA를 남긴다. 완료 후 자동으로 성능·비용 보고서와 분포별 표, 신뢰구간, 원자료 일치 검증, 통합 목록 갱신이 이어진다. 환경 전체 재시작 후 자동 재개까지 보장하지 않으며 동일 진입점을 다시 실행하면 완료 질문을 재사용한다.
