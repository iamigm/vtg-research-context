# 후속 설계: 시작 조건부 종료 예산의 분리와 적응 배분

이 문서는 설계이며 새 GPU 실행은 시작하지 않았다. 기존30개는 개발 표본으로 취급하고 결과를 보고 정책을 고르는 데 사용했음을 명시한다.

## 결과가 요구하는 변경

1. 시작 폭만 늘리는 balanced 정책은512확장에서 S를90.76%→93.74%로 높였지만 J는49.94%→39.95%로 낮췄고 decoder 계산은1,630.5→2,194.3토큰으로 늘었다. 종료 조건부 탐색에 예산을 확보해야 한다.
2. joint에서도512확장에 J≥.90이7/30뿐이다. 종료 분포 차이의 TV 범위가 넓고 시작별 K90 해결도41/3,706에 그쳤다. 기존 예산이 충분하다고 결론 내릴 수 없다. 이 비율은 미미한 확률의 시작도 포함하므로 주된 시작만 보는 질량 가중 분석이 필요하다.
3. 유효한 MM:SS 표기가 문법 밖으로 분류됐다. 문법 밖 질량을 제거하거나 무조건 예산 부족으로 부르지 않는다.
4. 전체 관측 후보 oracle은 상위16개 oracle보다 높다. 생성 질량·제안 후보 수·GT 없는 선택 성능을 따로 측정해야 한다.

## 1단계: 측정 문법과 비용 검증

- 기존 동일 모델·질문·프롬프트·2 FPS·공간 입력을 고정한다. 출력 형식을 강제하는 새 프롬프트는 별도 실험으로 분리한다.
- 초 단위 숫자와 MM:SS/HH:MM:SS, 관측된 소수 표기를 지원한다. 분·초 필드 유효 범위를 검사하며 허용 정밀도·시간 상한·출력 길이 상한을 설정에 기록한다. 추적 중 문법 밖 토큰 상위 항목과 질량을 저장해 미지원 표기와 실제 비시간 출력을 구분한다.
- 시작의 끝과 종료의 끝을 확정하는 토큰 경계를 명시한다. 숫자가 끝났는지 확인하지 않은 상태를 완성 시각으로 세지 않는다. 숫자와 delimiter를 함께 담는 토큰은 분리해서 존재하지 않는 prefix를 만들지 않는다.
- 정확한 토큰 prefix마다 조건부 분포를 유지한다. 같은 시각의 `131.0`과 `2:11`은 결과 표시에서만 초 단위로 합치며, 한 표기의 종료 분포를 다른 표기에 재사용하지 않는다. 경로 질량 합산은 disjoint 조건에서만 수행한다.
- 형식 밖 질량을 raw softmax에서 별도 보존한다. 0.90/0.95 도달 실패를 문법 제외·미탐색·길이 상한으로 분해한다. 지원 문법 안으로 재정규화한 수치는 보조 지표로만 따로 표기한다.
- 탐색 순서와 무관하게 decoder는1토큰씩 계산한다. 분기 rollback 대조 검증을 데이터셋별 최소1개씩 확대한다.
- 종료가 영상 길이를 조금 넘는 경우의 평가 정책을 고정한다. 주 평가는 원출력의 양의 구간 시간 IoU(반올림·clipping 없음), 엄격한 영상 범위 판정은 별도 민감도 분석으로 유지한다. 모든 방법의 greedy·후보·최종 선택에 같은 기준을 적용한다.

## 2단계: 종료 분포 자체를 측정하는 조건부 진단

전체 joint 트리에 예산을 쓰면서 종료 분포가 저절로 충분히 관측되기를 기다리지 않는다.

1. 시작-prefix를 결정적 확률순으로 탐색해 상위 시작들을 확보한다. 시작 탐색의 raw 누적 질량과 비용을 별도 기록한다.
2. 대표 시작 숫자의 상위2/4/8개를 조건으로 각각 종료 전용 트리를 탐색한다. 같은 숫자의 다른 토큰 표기를 대체하지 않고, 대표로 택한 정확한 prefix와 그 질량을 기록한다. 이 표본으로 전체 시작 공간의 포괄성을 주장하지 않는다.
3. 각 시작에서 종료 조건부 질량0.50/0.80/0.90에 도달한 decoder 비용, 종료 후보 수, 시간 분산, 미해결 꼬리를 기록한다. 단계별 확인에서 얻은 도달 비용은 최소 비용의 확정치가 아닌 상한이다.
4. 시작별 종료 분포 차이는 raw 부분분포의 TV 상·하한과 꼬리 질량으로 보고한다. 관측 후보를 정규화해 분포 차이를 과장하지 않는다. 상위 시작이 차지하는 질량으로 가중한 요약과 질문별 값을 모두 제공한다.
5. 동일 사건 여부는 이 수치로 판정하지 않는다. 서로 다른 시작으로 생성한 구간의 영상 내용 검토가 별도로 필요하다.

종료 전용 실행의 임시 decoder 상한은 시작-prefix당512토큰이고, 미해결 상위질량 prefix에 한해1,024/2,048토큰 확장을 비교한다. 이 비용은 전체 알고리즘 예산과 별도로 집계하는 진단 비용이다. 아직 적정값으로 확정한 것은 아니다.

## 3단계: 동일 실제 계산 예산에서 정책 비교

주 예산은 질문·정책당 추가 decoder1,024/2,048/4,096토큰이다. 한 번의4,096토큰 실행에서 앞 checkpoint를 기록한다. prefill은 한 번만 공유하며 별도 비용으로 보고한다. rollback 재계산, 대표 greedy 완성, 분기 후보 평가 비용을 모두 포함한다. CPU 후보 열거 시간과 실제 GPU/벽시계 시간도 보고한다.

| 정책 | 시작/종료 배분 | 목적 |
|---|---|---|
| 수정된 joint 우선 | 전체 경로 확률 우선 | v1의 기준 정책을 형식 수정 후 재평가 |
| 시작25% / 종료75% | 시작 예산 뒤 시작별 종료 탐색 | 종료에 충분한 예산을 남겼을 때의 효과 |
| 시작50% / 종료50% | 같은 구조의 다른 비율 | 비율 효과와 시작 coverage 손실 확인 |
| 적응 배분 | 아래 residual 규칙 | 고정 비율보다 효율적인지 검증 |

적응 배분은 시작 미확보 질량과 각 시작 아래 미완성 질량 `r_i=P(z_i)(1−C_i)`를 유지한다. 문법 밖 확정 질량은 더 탐색해 회수할 수 있는 residual과 분리한다. 이미 얻은 frontier 확률을 다음 확장 이득의 상한으로 보고, 예상 replay 비용 대비 우선순위를 정한다. 이는 실제 얻을 질량을 미리 아는 oracle 규칙이 아니므로 예측 상한과 실제 회수 질량을 함께 기록한다.

새 시작 분기를 열면 해당 prefix에서 끝까지 한 번 결정적으로 완성해 대표 구간을 확보한다. 이를 위한 실제 decoder 비용을 예산에 포함한다. 대표 결과에 시작 subtree 전체 질량을 부여하지 않고, 완성 경로의 실제 토큰 확률만 기록한다. 동일 토큰 경로는 재탐색하지 않는다.

초기 분기에는 greedy 대표를 붙이고 이후 조건부 종료를 탐색하는 정책은 단순 joint와 서로 다른 탐색 정책이다. 이 차이를 명시하고 동일 비용에서 비교한다. 예산이 부족해 대표조차 완성하지 못하면 unfinished로 남긴다.

소수 첫째자리 차이로 시작 후보가 늘어나는 문제는 별도 ablation으로 평가한다. 1초 근접 그룹은 예산 배분에만 활용하고 사건 cluster로 부르지 않는다. 각 prefix의 확률과 종료 분포는 계속 따로 유지하며 생략한 prefix 질량은 residual로 남긴다. 그룹 간 최소 배분을 적용했을 때와 적용하지 않았을 때를 비교한다.

## 후보 생성과 최종 선택의 평가 분리

- 확률: S, J, 유효 구간 질량, 문법 밖·미탐색 질량, 시작별 종료 coverage, TV 범위 폭. J≥.90/.95 도달 비용과 미도달 비율을 함께 보고한다.
- 후보: 전체 관측 후보 oracle과 관측 후보 중 확률 상위1/4/8/16 oracle을 분리한다. 원시 완성 경로 수와 수치상 고유 구간 수도 기록한다. 상위 후보가 전역 상위 후보로 증명되지 않으면 '관측 후보 중'이라고 표시한다.
- 실제 선택: GT 없는 경로확률 선택, temporal cluster 질량 선택, 동일 영상 입력을 쓰는 질문-구간 검증 선택을 비교한다. 검증 비용은 decoder 탐색 비용과 별도 및 합산 둘 다 보고한다. 합산 동일 예산 비교에서는 후보 생성에 쓸 수 있는 예산을 줄여 맞춘다.
- 성능: mIoU 및 IoU≥.3/.5/.7 성공률, greedy 대비 변화(pp), 영상 단위 paired bootstrap 신뢰구간. 영상 길이·GT/영상 길이 비율·두 축 교차표를 네 지표별로 제공한다.
- 경계: 같은 사건을 선택한 조건에서 시작·종료 MAE(초), GT 길이로 나눈 MAE, refinement 후 사건 이탈률. GT는 평가에만 쓰고 분기·선택·입력에는 쓰지 않는다.

## 사건 혼동과 refinement 가설의 다음 검증

예산 진단 후 기존30개의 관측 상위 후보를 영상으로 검토한다. 가까운 시간 후보와 떨어진 후보를 모두 포함하고, 가능하면2명이 독립적으로 동일 occurrence/다른 occurrence/질문에 부적합/다중 유효 답을 판정한다. 시간 간격 또는 TV만으로 사건 혼동을 선언하지 않는다.

이후 결과를 `사건 후보 발견 → 올바른 사건 선택 → 같은 사건 내 경계 개선`의 세 단계로 분해한다. 사건 후보가 발견되지 않는 실패와, 후보가 있지만 고르지 못하는 실패, 사건은 맞지만 경계를 못 맞추는 실패를 나눠야 사용자의 원래 가설에 답할 수 있다.

## 개발과 확인 표본

현재30개로 문법·예산·배분 정책을 개발한다. 정책을 고정한 뒤 기존 pilot300의 나머지 질문 중 개발30개와 영상이 겹치지 않는 질문들을 확인 표본으로 사용한다. 코호트 객체나 순서를 수정하지 않고 별도 mask·제외 사유·실제 질문/영상 수를 저장한다. 같은900 코호트로 확장할 때도 개발 영상 중복을 명시한다.

512 prefix 확장이 충분하지 않았다고 곧바로 전체300개에8배 예산을 주지는 않는다. 종료 전용 진단에서 어느 조건부 분포가 어려운지 확인한 뒤, 같은 계산량에서 joint보다 개선되는 정책을 선정한다. 확정 전에는 '권장 rollout 수'를 단일 숫자로 제시하지 않는다.
