## 4. 샘플링 구현

Uniform / Random-guided / GT-guided / Pred-guided를 비교하라. 상세 알고리즘은 SPEC.md를 따른다.

- Uniform은 기존 2fps ordered frame IDs를 재현한다.
- 나머지는 baseline frames에서 전역에 분포한 50% anchors를 유지하고, 나머지 50%를 길이 0.4T의 focus window에 배치한다.
- GT window 중심은 GT midpoint, Pred 중심은 uniform scout 첫 예측 구간 midpoint다.
- Random 중심은 GT와 독립적으로 생성한다. planner seeds는 42/43/44.
- 모든 조건에서 window 폭을 같게 하고, 영상 양끝에서는 폭을 유지하며 window를 이동한다.
- 후보는 실제 8fps와 2fps source frames의 합집합이다. 768 cap 때문에 후보가 부족하면 명세에 따라 원본에서 후보를 추가 추출하고 준비 비용을 기록한다.
- anchors와 중복되지 않는 window 내부 후보를 균등 rank로 선택하고, 부족하면 window까지의 거리가 가까운 후보로 채운다. fill 비율을 기록한다.
- 실제 source frames의 중복으로 예산을 맞추지 마라. processor padding은 따로 센다.
- Pred scout 파싱 실패·비유한·역전 구간은 Uniform fallback이다.
- final 프롬프트에 scout 답변이나 수정 지시를 추가하지 마라.

비균일 프레임을 가짜 일정 fps로 전달하지 마라. 원본 PTS와 duration, processor timestamp/temporal position의 대응을 검증하라. 설치 버전에서 이를 안전하게 표현할 수 없다면 본 실험을 중단하고 구체적인 원인과 대안을 보고하라. 임의 metadata 필드를 넣고 지원된다고 간주하지 마라.

같은 source frame의 RGB가 sampler별 seek나 cache 때문에 달라지지 않게 하라. decoder 변경이 필요하면 명세의 버전 분리 규칙을 따른다.

## 5. 데이터 누수와 비용

GT는 GT-guided planner와 생성 후 evaluator에서만 사용하라. Uniform·Random·Pred 계획은 GT를 제거·변조해도 동일해야 한다. 기존 IoU·정답 가능성 라벨·성공한 rollout을 선택 신호로 사용하지 마라.

공통 scout 100개, primary finals 400개, Random seed 43/44 sensitivity finals 200개로 최대 700개 응답이다. 기존 scout는 입력·모델·생성 설정의 동일성을 검증한 경우에만 재사용한다.

모든 조건은 공통 scout+final의 두 단계 정책으로 비용을 기록한다. final F_i/B_i와 누적 2F_i/2B_i를 구분하고, 자연스러운 single-pass Uniform 비용도 별도로 보여라. Pred를 single-pass Uniform과 동일 전체 비용이라고 표현하지 마라.

## 6. 구현과 실행 순서

1. 기존 구조에 맞는 최소 코드를 작성하고 SPEC.md를 새 결과 디렉터리에 보존한다.
2. 사전 검증을 완료하고 config·cohort·code·source hashes를 고정한다.
3. 공통 scout를 생성하거나 검증된 기존 결과를 연결한다.
4. final 생성 전에 모든 sampling plans를 저장·hash한다.
5. 성능과 무관한 sample ID 순 첫 5개에서 모든 조건 smoke 검사를 수행한다.
6. uniform adapter와 기존 prepare_pair의 pixels·IDs·timestamps·grid·positions를 비교한다.
7. 반복 Uniform, budget equality, GT 격리, decoder/cache, 저장·resume를 검증한다.
8. 통과하면 전체 실행을 백그라운드로 진행하고 로그·상태·완료 수를 남긴다.
9. 저장된 원본으로 평가·보고서를 생성하고 새 artifact 버전을 등록한다.

완료 응답은 원자적으로 저장하고 config/cohort/input/plan hash가 맞는 항목만 재개 시 건너뛰어라. OOM 때문에 특정 조건만 프레임·해상도를 낮추지 마라. 성능 중간 결과를 보고 parameter를 바꾸거나 조기 종료하지 마라.

## 7. 평가

주평가는 공용 extract_time으로 파싱한 첫 구간, raw seconds, 반올림·clipping 없음이다. 파싱 실패와 무효 구간은 IoU 0으로 전체 100개에 포함하라. 과거 Python round 평가값은 별도 호환성 표로 제공하라.

필수 출력:

- mIoU, R@1 IoU≥.3/.5/.7.
- query별 paired ΔIoU, 개선·악화·동일, .5 성공 전환.
- start/end 절대 오차와 정규화 오차, 실패를 포함한 boundary-within-1s/2s.
- GT frame fraction, ε=0.5초 temporal coverage 및 start/end boundary coverage.
- frame/token/grid equality, fill/fallback, 파싱·종료·범위 오류.
- scout/final과 CPU 후보 준비를 분리한 시간·VRAM·생성 토큰 비용.
- video ID 단위 paired cluster bootstrap 20,000회, seed 42, 95% CI.
- Random 세 seed와 query별 seed 평균. 300개 random 응답을 독립 query로 취급하지 말 것.

주비교는 GT−Uniform 및 Pred−Uniform이다. Random 대비 차이도 보고하라. CI는 탐색적이며 다중비교·일반화의 한계를 명시하라.

연구 판단 기준은 SPEC.md의 사전 기준을 따른다. GT +3pp, Pred +2pp 및 CI·Random 대조·R@.5 조건을 사후 변경하지 마라. GT-guided는 진단용 oracle reference이며 최적 상한이나 실용 방법으로 제시하지 마라.
